# chebu

Учебный и исследовательский проект по разработке кодинговых агентов с помощью кодинговых агентов. Мы изучаем минимальную реализацию на Python, используем ИИ-помощников для объяснения и развития кода и сохраняем занятия вместе со снимками изучаемых версий.

Исследуемый агент обращается к DeepSeek, выполняет запрошенные моделью команды и возвращает их результаты в историю сообщений.

Стартовая версия **v0.1.0** является учебным форком [chebupelka Алексея Голобурдина](https://github.com/alexey-goloburdin/chebupelka). В GitHub проект оформлен как самостоятельный репозиторий. Исходники получены через `upstream` и объединение историй; исходная история Git сохранена. Дальнейшее развитие ведётся под именем `chebu`. До v0.1.2 включительно проект назывался `chebupelkajev`; это имя сохранено в тегах и снимках тех выпусков.

Текущий выпуск: **v0.1.4**. Он позволяет вести учебную сессию с кодинговым агентом в любом из шести рантаймов: добавляет правила для агента, передачу сессии между рантаймами, режимы тьютора и тикеты в репозитории. Код и обучение разделены по каталогам; Python-команды выполняются из `agent/`. Логика агента и два существующих теста сохранены.

## Как создаются код и учебные материалы

Пакеты уроков **v0.1.0**, **v0.1.1** и **v0.1.2**, документация и подготовка этих состояний репозитория выполнены в совместной работе владельца проекта и **OpenAI Codex**. Владелец задаёт цели, согласует решения и проверяет результаты; Codex исследует код, объясняет действия, готовит изменения и выполняет проверки. Переименование в `chebu` и документы выпуска **v0.1.3** подготовлены с помощью **Claude Code**. Правила для агентов, передача сессии и режимы тьютора подготовлены с помощью Claude Code и проверены совместной сессией шести рантаймов. Документы выпуска **v0.1.4** также подготовлены с помощью Claude Code.

| Агент | Участие в текущем состоянии проекта |
|---|---|
| OpenAI Codex, ведущий агент сессий v0.1.0–v0.1.2 | Пошаговое обучение, настройка проекта, общая документация, организация работы и публикация выпусков |
| Вспомогательные агенты Codex с назначенной моделью `gpt-6.1-sol` | Подробные уроки трёх пакетов, переименование и перенос файлов, локальные тесты и независимая проверка изменений |
| Claude Code с моделью Claude Opus 5.5 | Переименование проекта в `chebu`, проверка ссылок, перестройка трекера и документы выпуска v0.1.3; в v0.1.4 правила для агентов, передача сессии между рантаймами, режимы тьютора, тикеты в репозитории и документы выпуска |
| Claude Code, Codex, OpenCode, Grok, Cursor и Devin | Проверочная сессия v0.1.4: шесть рантаймов по очереди продолжили одну учебную сессию по снимку |
| DeepSeek с API-именем `deepseek-flash` | Модель внутри исследуемого агента; участвовала в проверке подключения и выполнении учебной задачи `pwd` |

Уроки v0.1.0–v0.1.2 созданы с помощью Codex. DeepSeek используется как модель запускаемого `chebu`. Исходная минимальная реализация принадлежит автору upstream-проекта. Дальнейшие занятия будут фиксировать, какие агенты участвовали, что было изменено и какими проверками подтверждён результат.

Вести сессию может любой из шести рантаймов: Codex, Claude Code, OpenCode, Grok, Cursor, Devin. Правила для них записаны в [AGENTS.md](AGENTS.md). [Протокол передачи](.handoff/README.md) позволяет закрыть сессию в одном рантайме и продолжить в другом.

## Начать обучение с кодинговым агентом

1. Клонируй репозиторий и перейди в его корень.
2. Запусти в корне любой из шести рантаймов: `claude`, `codex`, `opencode`, `grok`, `cursor-agent` или `devin`.
3. Набери команду навыка `chebu-tutor` с флагом режима, например `/chebu-tutor --walkthrough разберём agent/chebu.py`. В Codex команда начинается с `$`: `$chebu-tutor --walkthrough`. Если режим ещё не выбран, набери `/chebu-tutor` без флага.

Агент проверит флаг, прочитает [AGENTS.md](AGENTS.md) и сообщит о первой сессии. Режим из флага он подтвердит одной строкой, а без флага покажет [режимы тьютора](coding-agent-developement/tutor-modes.md) и спросит один раз. Затем он предложит выбрать [тикет](coding-agent-developement/tickets/README.md). В конце сессии агент сохранит снимок в `.handoff/`. Следующую сессию можно открыть в другом рантайме, и агент продолжит с того же места.

Флаги, команды по ситуациям и разбор ошибок описывает [инструкция по навыку](chebu-tutor-skill/README.md). Если навыка нет, например в облачной сессии, начни фразой «Начни учебную сессию»: агент начнёт ту же сессию без проверки флага.

Для учёта задач GitHub не нужен. Запросы `chebu` к DeepSeek платные и требуют твоего ключа. Локальные тесты работают без ключа.

## Как проходит учебная сессия

Этот порядок появился в v0.1.4. В сессии участвуют двое. Ты ставишь цель и принимаешь решения. Кодинговый агент ведёт сессию по правилам из [AGENTS.md](AGENTS.md). Агент, который ведёт сессию, и `chebu`, которого ты изучаешь, являются разными программами.

```text
Ты: /chebu-tutor --<режим> [цель]
        |
        v
Агент: python3 .handoff/handoff.py start --runtime <id> --mode
        |
        +-- два флага или неверный флаг --> строка использования, работа не начинается
        |
        +-- снимка нет ----> первая сессия: цель, режим из флага, тикет
        |
        +-- снимок есть ---> продолжение: режим из флага или из снимка,
        |                    шаг из снимка, сверка снимка с Git,
        |                    согласование плана
        v
Работа по тикету в выбранном режиме
        |
        v
Ты: «Закрой сессию»
        |
        v
Агент: python3 .handoff/handoff.py save
        |
        v
Снимок в .handoff/SESSION.md, прежний снимок в .handoff/archive/
        |
        v
Следующая сессия в этом же или в другом рантайме
```

### Первая сессия

Агент подставляет id своего рантайма: `claude`, `codex`, `cursor`, `devin`, `grok` или `opencode`. В свежем клоне вывод команды `start` заканчивается сообщением, что снимка нет:

```text
Снимок: нет. Это первая сессия в этом клоне.
Архив: пусто
Дальше: прочитай .handoff/README.md, раздел «Первая сессия».
```

После этого агент проверяет состояние Git и спрашивает о цели сессии. Если ты назвал режим флагом, агент начинает в нём. Без флага он показывает пять режимов тьютора и вместе с тобой выбирает режим. Тикет вы выбираете вместе. До твоего согласия с планом файлы проекта остаются без изменений.

### Режим и тикет

Режим определяет, кто меняет код тикета. Тикет описывает одну доработку `chebu`: что изменить, как проверить результат и на какой версии кода начинать.

| Ты хочешь | Режим | Кто меняет код тикета |
|---|---|---|
| Увидеть весь путь тикета | `execute` | Агент, по согласованному плану |
| Написать решение самому | `guide` | Ты, агент даёт подсказки по уровням |
| Разобрать код без правок | `walkthrough` | Никто |
| Увидеть поведение на примере | `sandbox` | Никто, агент пишет примеры в `.sandbox/` |
| Проверить понимание | `quiz` | Никто |

Режим меняется в любой момент командой `/chebu-tutor --<режим>` или обычной фразой, например «дальше пишу сам». Правила каждого режима и пример сессии в пяти режимах описывает [tutor-modes.md](coding-agent-developement/tutor-modes.md). Двенадцать тикетов лежат в [tickets/](coding-agent-developement/tickets/README.md).

### Где хранится твоя работа

| Что | Где | В Git |
|---|---|---|
| Правила для агента | [AGENTS.md](AGENTS.md) | Да |
| Протокол, шаблон и скрипт передачи | [.handoff/README.md](.handoff/README.md), `TEMPLATE.md`, `handoff.py` | Да |
| Тексты тикетов | [coding-agent-developement/tickets/](coding-agent-developement/tickets/README.md) | Да |
| Конфигурации рантаймов | `runtime-config/` | Да |
| Твои правки кода тикета | Рабочее дерево и ветка твоего клона | Да, после твоего коммита |
| Режим, прогресс по тикетам, вопросы и ответы | `.handoff/SESSION.md` и `.handoff/archive/` | Нет |
| Примеры режима `sandbox` | `.sandbox/` | Нет |

Снимок остаётся на твоей машине. Новый clone получает правила, протокол и тикеты, но не получает твой прогресс. Чтобы продолжить на другой машине, перенеси `SESSION.md` и `archive/` сам.

### Продолжить в другом рантайме

Команда `save` проверяет снимок и убирает прежний снимок в архив. Её вывод заканчивается командами запуска для каждого рантайма:

```text
Продолжить в любом рантайме из корня основного клона:
  claude "Продолжи работу по AGENTS.md и .handoff/SESSION.md."
  codex "Продолжи работу по AGENTS.md и .handoff/SESSION.md."
  cursor-agent "Продолжи работу по AGENTS.md и .handoff/SESSION.md."
  devin -- "Продолжи работу по AGENTS.md и .handoff/SESSION.md."
  grok "Продолжи работу по AGENTS.md и .handoff/SESSION.md."
  opencode --prompt "Продолжи работу по AGENTS.md и .handoff/SESSION.md."
```

Вместо этих команд можно открыть рантайм в корне клона и набрать `/chebu-tutor` без флага: режим возьмётся из снимка. С флагом сессия продолжится в режиме флага.

Новый агент выполняет `start` и называет режим из снимка. Затем он читает снимок, заново проверяет то, что снимок говорит о Git и о тикете, и предлагает одно следующее действие. Режим агент повторно не спрашивает. Работа продолжается после твоего согласия с планом.

### Что проверено и что нет

13 октября 2026 года шесть рантаймов по очереди продолжили одну учебную сессию. Каждый сам выполнил `start`. Режим пять раз перешёл из рантайма в рантайм без повторного вопроса.

- Код тикета в этой сессии не правил никто. Правка агента в режиме `execute` и проверка твоей правки в режиме `guide` остались непроверенными.
- Границы записи в режимах задаёт инструкция. Скрипт не отличает правку агента от твоей, поэтому после шага проверяй `git status --short`.
- Облачные сессии и агент внутри приложения Cursor не проверялись. Облачная сессия локальную папку `.handoff/` не видит.
- Полная первая сессия в свежем клоне под управлением рантайма не проводилась. Проверена команда `start` в таком клоне.

### С какого снимка начинать

Код `agent/chebu.py` в v0.1.4 совпадает с версией v0.1.1, поэтому все двенадцать тикетов открыты. Начинай с `main` своего клона. Когда тикет будет решён в `main`, начни его с тега v0.1.4 на своей ветке. Команда записана в [VERSIONING.md](VERSIONING.md). Это первый тег, который содержит `AGENTS.md` и тикеты.

## Установить и запустить chebu

В новой директории:

```bash
git clone https://github.com/alanbigulov/chebupelka-jev.git
cd chebupelka-jev/agent
uv sync --locked
```

Нужен [uv](https://docs.astral.sh/uv/). Он выбирает Python 3.14 из `.python-version` и создаёт `agent/.venv`. Проект проверен с uv 0.5.15 и 0.12.14.

Ввод ключа DeepSeek в **zsh**:

```zsh
read -rs "DEEPSEEK_API_KEY?Вставь ключ DeepSeek и нажми Enter: "
printf '\n'
export DEEPSEEK_API_KEY
```

```bash
uv run python chebu.py "Вызови инструмент bash ровно один раз с командой pwd. Затем сообщи текущую директорию и заверши работу. Файлы не изменяй."
```

Ключ действует в текущей сессии терминала, не записывается в исходники и не читается из `.env` автоматически. Проверки без ключа и без обращения к API выполняются из `agent/`:

```bash
uv run python -m unittest discover -s tests -v
```

> [!WARNING]
> Агент выполняет shell-команды с правами пользователя, без подтверждения и изоляции. Учебный worktree не ограничивает эти права. Облачные запросы платные; текущий предел составляет 1000 ходов.

```text
chebupelka-jev/
├── README.md, VERSIONING.md, CHANGELOG.md    общие документы
├── AGENTS.md, CLAUDE.md                    правила для ведущего агента

├── runtime-config/                         конфигурации рантаймов
├── .claude/skills/, .agents/skills/        адаптеры навыка chebu-tutor
├── chebu-tutor-skill/                      разработка навыка chebu-tutor
├── agent/                                  исполняемый Python-проект
│   ├── chebu.py
│   ├── pyproject.toml, uv.lock, .python-version
│   ├── README.md
│   └── tests/fixtures/
└── coding-agent-developement/               учебные материалы
    ├── README.md, project-structure.md
    ├── development-roadmap.md
    ├── tutor-modes.md, project-tracking.md
    ├── tickets/                            тексты тикетов EDU

    ├── lessons-v0.1.1/

    ├── lessons-v0.1.3/
```

Реализация: [agent/chebu.py](agent/chebu.py). Прямая зависимость: `requests`. Внутренние функции не разделялись на новые модули.

```text
Задача → agent_loop() → call_llm() → DeepSeek
              ^                         |
              |                  текст или tool_calls
              |                         |
              +── результат ← call_tool() → run_bash()
```

## Развернуть старую версию

Из корня основного репозитория, если соседней папки ещё нет:

```bash
git worktree add --detach ../chebupelkajev-v0.1.0 v0.1.0
cd ../chebupelkajev-v0.1.0
uv sync --locked
```

В снимке v0.1.0 исходник находится в корне. В v0.1.1 он находится в `agent/`. Для уже созданной папки повторный `worktree add` не нужен: перейди в неё и следуй [паспорту v0.1.0](coding-agent-developement/lessons-v0.1.0/version.md).

Тег сохраняет код и зависимости, но не фиксирует облачную модель под именем `deepseek-flash`. Подробности восстановления и ограничений описаны в [уроке о снимках](coding-agent-developement/lessons-v0.1.1/01-structure-and-snapshots.md).

Продолжай с [исходных трёх уроков v0.1.0](coding-agent-developement/README.md) и затем с пакетами v0.1.1 и [v0.1.2](coding-agent-developement/lessons-v0.1.2/01-github-project-tracking.md). Переименование описывает [паспорт v0.1.3](coding-agent-developement/lessons-v0.1.3/version.md), текущее состояние описывает [паспорт v0.1.4](coding-agent-developement/lessons-v0.1.4/version.md). Исходное [видео автора](https://www.youtube.com/watch?v=H7FSTj4x4xQ) объясняет минимальную реализацию, от которой начался проект.
