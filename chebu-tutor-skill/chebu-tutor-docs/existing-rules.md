# Скрипты и регламенты, которые выполняет chebu-tutor

Навык `chebu-tutor` своих правил тьютора не вводит. Он выполняет правила и скрипты, которые уже есть в репозитории, и добавляет к ним один вход: флаг режима. Этот справочник перечисляет каждый такой источник, место в нём и то, что с ним делает навык.

Исходные файлы главнее справочника. Перед каждым этапом разработки сверяй таблицы ниже с текущими файлами. Если источник изменился, сначала обнови этот справочник, затем контракт.

## Правила ведущего агента

[AGENTS.md](../../AGENTS.md) читают все шесть рантаймов. Claude Code получает его через строку `@AGENTS.md` в [CLAUDE.md](../../CLAUDE.md). Адаптер навыка текст AGENTS.md не копирует.

| Раздел AGENTS.md | Что задаёт | Что делает навык |
|---|---|---|
| «Начни сессию» | Четыре шага: `python3 .handoff/handoff.py start --runtime <id>`, раздел протокола и снимок, перепроверка Git и тикета, объяснение состояния и одного следующего действия. До согласования плана файлы проекта не меняются | Выполняет те же шаги в том же порядке |
| «Веди сессию» | Русский язык, цель перед действием и результат после него, решения за учеником, одно следующее действие, имя `chebu`, локальные тесты из `agent/` | Следует без изменений |
| «Режим тьютора» | Пять режимов, режим из снимка без вопроса, вопрос один раз, если режима нет, смена режима обычной фразой | Флаг задаёт режим так же, как фраза ученика о смене режима |
| «Границы» | Платный запрос к DeepSeek, коммит, push, PR, тег, issues и Project только с разрешения в текущей сессии. Состояние `.handoff/` не попадает в Git. Ключи, `.env` и журналы авторизации не читаются | Флаг разрешений не даёт |
| «Закрой сессию» | Сбор фактов, `SESSION.next.md` по шаблону, `handoff.py save`, отчёт ученику | Выполняет по фразе ученика «закрой сессию» |
| «Куда смотреть» | Карта документов по ситуациям | Использует как карту, сам карту не дублирует |

## Режимы тьютора

[tutor-modes.md](../../coding-agent-developement/tutor-modes.md) задаёт поведение в каждом режиме. Флаг навыка выбирает раздел этого документа.

| Раздел tutor-modes.md | Что задаёт |
|---|---|
| «Пять режимов» | id режима, кто меняет код тикета, куда пишет агент |
| «Выбор и смена режима» | Режим из флага `/chebu-tutor` или из снимка, смена флагом или фразой, подтверждение смены одной строкой, запись id режима в снимок при закрытии |
| `execute`, `guide`, `walkthrough`, `sandbox`, `quiz` | Пошаговые правила режима и то, что записать в снимок |
| «Что режим не контролирует» | Границу записи проверяет `git status --short` до шага и после него. В `quiz` рантайм может показать ответ в рассуждениях модели |
| «Как начать сессию» | Команда `/chebu-tutor --<режим>` как способ начать сессию по умолчанию, команды по ситуациям и режимам, разрешения словами. Подраздел «Без навыка: промпт» хранит промпты для случаев без навыка. Раздел переписан 2026-10-19 |

Список id режимов для кода хранит строка «Режим тьютора» таблицы метаданных [TEMPLATE.md](../../.handoff/TEMPLATE.md): `execute / guide / walkthrough / sandbox / quiz`. Скрипт `handoff.py` разбирает такую строку как перечисление (`Snapshot.enumerations`), проверяет по нему снимок и печатает режим в выводе `start`. Флаги навыка получаются из того же перечисления: `--` и id режима.

## Передача сессии

[Протокол](../../.handoff/README.md) описывает, как сессия переходит между рантаймами.

| Раздел протокола | Что использует навык |
|---|---|
| §1 «Файлы и границы» | Состояние лежит в основном клоне и исключено из Git. В git worktree `SESSION.next.md` пишется в `.handoff/` рабочей копии |
| §2 «Рантаймы» | Агент называет свой рантайм ключом `--runtime`. Без ключа `start` распознаёт рантайм по переменной окружения, а при неудаче завершается с кодом 2. У Devin переменной нет |
| §3 «Что считать доказанным» | Метки «Проверено», «Не проверено», «Частично», «Блокировано», «Предложение» |
| §4 «Первая сессия» | Порядок, когда снимка и архива нет |
| §5 «Возобновление сессии» | Порядок, когда снимок есть. Режим из снимка продолжается без вопроса |
| §6 и §7 «Закрытие сессии» | Сбор фактов, заполнение шаблона, `save` |

[TEMPLATE.md](../../.handoff/TEMPLATE.md) задаёт 11 разделов снимка. Навыку важны три места: строка «Режим тьютора» в метаданных, раздел 8 «Учебное состояние» и раздел 11 «Как продолжить».

### Команды handoff.py

[handoff.py](../../.handoff/handoff.py) запускается из корня рабочей копии.

| Команда | Что делает | Код выхода | Что важно навыку |
|---|---|---|---|
| `start --runtime <id>` | Печатает рантайм, его конфигурацию, путь к состоянию, рабочую копию, сводку снимка с полями-перечислениями, архив и раздел протокола, который читать дальше | 0. Код 2, если id нет в реестре, если без ключа рантайм не распознан и при неверных аргументах | Строка `Режим тьютора: <id>` содержит режим из снимка. `start --runtime unknown` печатает `Рантайм: неизвестен (unknown)` и завершается с кодом 0 |
| `start --runtime <id> --mode` | Читает слова вызова навыка из stdin и проверяет флаг режима до брифинга. Затем печатает тот же брифинг, где строка режима сравнивает флаг со снимком. Без флага сначала печатает строку использования | 0. Код 2 при двух флагах или флаге вне списка: в stderr причина и строка использования, stdout пуст | Исполняет ENF-001. Ключ добавлен на этапе 3 (D-16), интерфейс описан в [контракте](contract.md#команда-проверки) |
| `check [ПУТЬ]` | Проверяет снимок по шаблону. Без пути берёт `SESSION.next.md` | 0 или 1 | Режим в снимке должен входить в перечисление шаблона |
| `save` | Проверяет `SESSION.next.md`, убирает прежний `SESSION.md` в `archive/`, ставит новый снимок и печатает команды продолжения для шести рантаймов | 0 или 1 | Команды продолжения рассчитаны на корень основного клона |

[test_handoff.py](../../.handoff/test_handoff.py) содержит 74 теста, из них 11 в классе `ModeTest` проверяют ключ `--mode`. Запуск из корня:

```bash
python3 -m unittest discover -s .handoff -p 'test_*.py' -v
```

Несколько тестов защищают то, на что опирается навык: `test_agents_md_names_every_runtime_id`, `test_manifest_lists_exactly_the_runtime_files`, `test_names_and_markers_identify_one_runtime`, `test_prints_one_line_per_enumerated_field_of_real_template`.

## Реестр рантаймов

[manifest.json](../../runtime-config/manifest.json) хранит схему, промпт продолжения `resume_prompt` и список id: `claude`, `codex`, `cursor`, `devin`, `grok`, `opencode`. Каждый id описан своим файлом:

| Рантайм | Файл |
|---|---|
| Claude Code | [claude.json](../../runtime-config/runtimes/claude.json) |
| Codex | [codex.json](../../runtime-config/runtimes/codex.json) |
| Cursor | [cursor.json](../../runtime-config/runtimes/cursor.json) |
| Devin | [devin.json](../../runtime-config/runtimes/devin.json) |
| Grok Build | [grok.json](../../runtime-config/runtimes/grok.json) |
| OpenCode | [opencode.json](../../runtime-config/runtimes/opencode.json) |

Поля файла рантайма: `schema`, `id`, `name`, `aliases`, `cli`, `entry_files`, `detect_env`, `commands` (`start`, `headless`, `continue`) и `checked` (`date`, `cli_version`, `confirmed`, `unconfirmed`). Функция `load_runtime` в `handoff.py` читает только `id`, `name`, `aliases`, `entry_files`, `detect_env`, `commands.start` и `checked.unconfirmed`. Остальные ключи она пропускает, поэтому новый блок с фактами об адаптере навыка `handoff.py` не ломает.

Этап 4 добавил в каждый файл блок `skill`: поле `dir` и у Codex поле `link_to` (D-21). Блок читает только генератор `chebu-tutor-skill/tools/sync.py`. Список id генератор получает через `load_registry` из `handoff.py`, поэтому рантайм из `manifest.json` без блока `skill` роняет `--check`.
