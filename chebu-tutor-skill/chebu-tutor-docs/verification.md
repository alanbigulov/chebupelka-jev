# Проверки навыка chebu-tutor

Навык проверяется на двух уровнях. Автоматические проверки работают локально, бесплатно и без сети. Ручная приёмка запускает навык в шести рантаймах и требует разрешения владельца, потому что каждый запуск расходует лимит модели рантайма. Платный запрос к DeepSeek ни одной проверке не нужен.

Метки итога совпадают с разделом «Что считать доказанным» [протокола](../../.handoff/README.md): «Проверено», «Не проверено», «Частично», «Блокировано».

## Автоматические проверки

Команды выполняются из корня рабочей копии.

| Проверка | Команда | Появляется | Что доказывает |
|---|---|---|---|
| Протокол передачи сессии | `python3 -m unittest discover -s .handoff -p 'test_*.py' -v` | Уже есть, 63 теста | Навык не сломал `handoff.py` |
| Тесты навыка | `python3 -m unittest discover -s chebu-tutor-skill/tests -v` | Этап 2 | Разбор флага, `skill.json`, синхронизация |
| Синхронизация адаптеров | `python3 chebu-tutor-skill/tools/sync.py --check` | Этап 4 | Адаптеры совпадают с источником и версией |
| Пробелы в изменениях | `git diff --check` | Уже есть | В diff нет висящих пробелов и конфликтных маркеров |
| Тесты `chebu` | `uv run python -m unittest discover -s tests -v` из `agent/` | Уже есть | Код агента не задет. Нужны, только если этап менял `agent/` |

Перед каждым коммитом этапа запускаются все проверки, которые к этому этапу уже существуют.

## Какие дефекты ловят тесты навыка

Тест считается полезным, если ловит конкретный дефект. Для каждого теста ниже назван дефект, на котором тест должен упасть. При написании теста этот дефект вносится вручную, тест запускается и должен упасть с ожидаемым сообщением. Только после этого дефект убирается.

| Тест | Дефект, который тест обязан поймать | Этап |
|---|---|---|
| Формат `skill.json` | Версия `0.1` вместо `0.1.0`. Имя навыка не `chebu-tutor` | 2 |
| Схема снимка | `requires.handoff_schema` не равна схеме в TEMPLATE.md | 2 |
| Один флаг | `--guide` с текстом ученика не даёт режим `guide` | 3 |
| Без флага | Отсутствие флага приводит к отказу, а не к поведению по решению D-08 | 3 |
| Два флага | `--guide --quiz` принят, или после отказа напечатан брифинг `start` | 3 |
| Неизвестный флаг | `--exec` или `--help` принят как режим | 3 |
| Опасный текст ученика | Кавычки, `$HOME`, обратные кавычки или перевод строки в тексте ученика меняют результат разбора или выполняются shell | 3 |
| Флаги равны перечислению | В копии шаблона добавлен режим, а проверка проходит | 3 |
| `$ARGUMENTS` в источнике | В `source/SKILL.md` нет `$ARGUMENTS`, а тест содержания проходит | 3 |
| Дрейф адаптера | Один байт адаптера изменён вручную, а `--check` проходит или не называет файл | 4 |
| Дрейф версии | `version` в `skill.json` изменена без генерации, а `--check` проходит | 4 |
| Новый рантайм | id добавлен в копию `manifest.json` без блока `skill`, а `--check` проходит | 4 |
| Повторная генерация | Второй запуск `sync.py` меняет хотя бы один файл | 4 |
| Чужие каталоги | Генератор пишет файл вне путей из блоков `skill` | 4 |
| Копия вместо ссылки | В `.agents/skills/chebu-tutor` лежит обычная папка или ссылка в другое место, а `--check` проходит | 4 |

Тесты работают на временной копии нужных файлов, как `test_handoff.py` работает на копии `runtime-config/`. Настоящее рабочее дерево тест не меняет.

## Ручная приёмка в рантаймах

Приёмку проводит этап 6. Этап 1 проводит её облегчённую часть с пробным навыком.

### Подготовка

1. Получи разрешение владельца в текущей сессии. Назови число запусков и рантаймы.
2. Создай одноразовый клон вне основного: `git clone <URL origin> /tmp/chebu-tutor-acceptance`. Снимок владельца в основном клоне приёмка не трогает.
3. В одноразовом клоне создай синтетический `.handoff/SESSION.md` с режимом `execute` и проверь его: `python3 .handoff/handoff.py check .handoff/SESSION.md`.
4. Перед каждым случаем сними `git status --short`. После случая сними ещё раз.

### Матрица

Каждый случай выполняется в каждом из шести рантаймов. Точная команда вызова для рантайма берётся из [runtime-adapters.md](runtime-adapters.md).

| Случай | Вызов | Что должно наблюдаться |
|---|---|---|
| A | `--walkthrough` при режиме `execute` в снимке | В выводе есть `Рантайм:` с id этого рантайма. Смена режима подтверждена одной строкой. `git status --short` не изменился |
| B | `--quiz` | Один вопрос. Ответа нет ни в сообщении, ни в выводе команд до ответа ученика |
| C | `--guide` | Шаг сформулирован как задача с командой проверки. Агент ждёт код. Подсказка уровня 1 только по просьбе |
| D | `--sandbox` | Новые файлы только в `.sandbox/`. Агент показывает команду и вывод |
| E | `--execute` | До правок агент предлагает план и ждёт согласия |
| F | Без флага | Строка использования, затем режим из снимка |
| G | `--guide --quiz` | Строка использования. Строк `Рантайм:` и `Снимок:` нет: брифинг не печатался, снимок не читался |
| H | `--guide` из папки вне клона | Сообщение, что навык работает только в клоне. Команды не запускались |
| I | Случай A, затем «закрой сессию» | `handoff.py check` проходит. В `SESSION.md` строка «Режим тьютора» равна `walkthrough` |

Матрица содержит 54 ячейки. Выпуск требует итога «Проверено» в каждой. Ячейку с другим итогом владелец может принять явно в сессии выпуска, и это решение записывается в журнал приёмки вместе с причиной.

### Журнал приёмки

Каждый запуск добавляет строку. Прежние строки не меняются.

| Дата UTC | Версия навыка | Рантайм и версия CLI | Случай | Команда вызова | Наблюдение | Итог |
|---|---|---|---|---|---|---|
| нет записей | | | | | | |

Нарушение правила из [контракта](contract.md) записывается в столбец «Наблюдение» с номером правила, например `ENF-105: ответ виден в рассуждениях`.
