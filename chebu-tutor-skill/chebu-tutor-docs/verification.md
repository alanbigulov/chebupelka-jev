# Проверки навыка chebu-tutor

Навык проверяется на двух уровнях. Автоматические проверки работают локально, бесплатно и без сети. Ручная приёмка запускает навык в шести рантаймах и требует разрешения владельца, потому что каждый запуск расходует лимит модели рантайма. Платный запрос к DeepSeek ни одной проверке не нужен.

Метки итога совпадают с разделом «Что считать доказанным» [протокола](../../.handoff/README.md): «Проверено», «Не проверено», «Частично», «Блокировано».

## Автоматические проверки

Команды выполняются из корня рабочей копии.

| Проверка | Команда | Появляется | Что доказывает |
|---|---|---|---|
| Протокол передачи сессии | `python3 -m unittest discover -s .handoff -p 'test_*.py' -v` | Уже есть: 63 теста, после этапа 3 их 74 | Навык не сломал `handoff.py`, ключ `--mode` разбирает флаг |
| Тесты навыка | `python3 -m unittest discover -s chebu-tutor-skill/tests -v` | Этап 2 | Разбор флага, `skill.json`, синхронизация |
| Синхронизация адаптеров | `python3 chebu-tutor-skill/tools/sync.py --check` | Этап 4 | Адаптеры совпадают с источником и версией |
| Пробелы в изменениях | `git diff --check` | Уже есть | В diff нет висящих пробелов и конфликтных маркеров |
| Тесты `chebu` | `uv run python -m unittest discover -s tests -v` из `agent/` | Уже есть | Код агента не задет. Нужны, только если этап менял `agent/` |

Перед каждым коммитом этапа запускаются все проверки, которые к этому этапу уже существуют.

## Какие дефекты ловят тесты навыка

Тест считается полезным, если ловит конкретный дефект. Для каждого теста ниже назван дефект, на котором тест должен упасть. При написании теста этот дефект вносится вручную, тест запускается и должен упасть с ожидаемым сообщением. Только после этого дефект убирается.

| Тест | Дефект, который тест обязан поймать | Этап |
|---|---|---|
| Формат `skill.json` | Версия `0.1` вместо `0.1.0`. Имя навыка не `chebu-tutor` | 2 |
| Схема снимка | `requires.handoff_schema` не равна схеме в TEMPLATE.md | 2 |
| Один флаг | `--guide` с текстом ученика не даёт режим `guide` | 3 |
| Без флага | Отсутствие флага приводит к отказу, а не к поведению по решению D-08 | 3 |
| Два флага | `--guide --quiz` принят, или после отказа напечатан брифинг `start` | 3 |
| Неизвестный флаг | `--exec` или `--help` принят как режим | 3 |
| Опасный текст ученика | Кавычки, `$HOME`, обратные кавычки или перевод строки в тексте ученика меняют результат разбора или выполняются shell | 3 |
| Флаги равны перечислению | В копии шаблона добавлен режим, а проверка проходит | 3 |
| `$ARGUMENTS` в источнике | В `source/SKILL.md` нет `$ARGUMENTS`, а тест содержания проходит | 3 |
| Дрейф адаптера | Один байт адаптера изменён вручную, а `--check` проходит или не называет файл | 4 |
| Дрейф версии | `version` в `skill.json` изменена без генерации, а `--check` проходит | 4 |
| Новый рантайм | id добавлен в копию `manifest.json` без блока `skill`, а `--check` проходит | 4 |
| Повторная генерация | Второй запуск `sync.py` меняет хотя бы один файл | 4 |
| Чужие каталоги | Генератор пишет файл вне путей из блоков `skill` | 4 |
| Копия вместо ссылки | В `.agents/skills/chebu-tutor` лежит обычная папка или ссылка в другое место, а `--check` проходит | 4 |
| Папка на месте ссылки при записи | Запуск записи удаляет папку, которая лежит на месте ссылки, или падает с трассировкой | 4 |
| Путь вне дерева | Блок `skill` с `..`, абсолютным путём или чужим именем папки принят, и генератор пишет туда | 4 |
| Пути из блоков | Блоки переносят папку навыка, а генератор пишет в прежние каталоги | 4 |
| `--check` только читает | `--check` создаёт или меняет хотя бы один путь | 4 |
| Папка повторяет источник | Ссылка Codex записана копией или абсолютным путём, нет `agents/openai.yaml`, пометка о генерации не первая строка тела | 4 |
| Лишний файл в адаптере | В папке адаптера лежит файл, которого нет в `source/`, а `--check` проходит или запись его удаляет | 4 |
| Запись через ссылку | Папка адаптера или его файл являются ссылкой, и генератор пишет по ней за пределы путей блоков или считает файл совпадающим | 4 |
| Несогласованные блоки | Опечатка в поле блока, два блока с разным описанием одной папки или `link_to` на папку, которую никто не пишет, приняты | 4 |
| Новый режим | В копии шаблона добавлен или убран режим, а `--check` проходит | 4 |

Тесты работают на временной копии нужных файлов, как `test_handoff.py` работает на копии `runtime-config/`. Настоящее рабочее дерево тест не меняет.

## Ручная приёмка в рантаймах

Приёмку проводит этап 6. Этап 1 проводит её облегчённую часть с пробным навыком.

### Подготовка

1. Получи разрешение владельца в текущей сессии. Назови число запусков и рантаймы.
2. Создай одноразовый клон вне основного: `git clone <URL origin> /tmp/chebu-tutor-acceptance`. Снимок владельца в основном клоне приёмка не трогает.
3. В одноразовом клоне создай синтетический `.handoff/SESSION.md` с режимом `execute` и проверь его: `python3 .handoff/handoff.py check .handoff/SESSION.md`.
4. Перед каждым случаем сними `git status --short`. После случая сними ещё раз.

### Матрица

Каждый случай выполняется в каждом из шести рантаймов. Точная команда вызова для рантайма берётся из [runtime-adapters.md](runtime-adapters.md).

| Случай | Вызов | Что должно наблюдаться |
|---|---|---|
| A | `--walkthrough` при режиме `execute` в снимке | В выводе есть `Рантайм:` с id этого рантайма. Смена режима подтверждена одной строкой. `git status --short` не изменился |
| B | `--quiz` | Один вопрос. Ответа нет ни в сообщении, ни в выводе команд до ответа ученика |
| C | `--guide` | Шаг сформулирован как задача с командой проверки. Агент ждёт код. Подсказка уровня 1 только по просьбе |
| D | `--sandbox` | Новые файлы только в `.sandbox/`. Агент показывает команду и вывод |
| E | `--execute` | До правок агент предлагает план и ждёт согласия |
| F | Без флага | Строка использования, затем режим из снимка |
| G | `--guide --quiz` | Строка использования. Строк `Рантайм:` и `Снимок:` нет: брифинг не печатался, снимок не читался |
| H | `--guide` из папки вне клона | Сообщение, что навык работает только в клоне. Команды не запускались |
| I | Случай A, затем «закрой сессию» | `handoff.py check` проходит. В `SESSION.md` строка «Режим тьютора» равна `walkthrough` |

Матрица содержит 54 ячейки. Выпуск требует итога «Проверено» в каждой. Ячейку с другим итогом владелец может принять явно в сессии выпуска, и это решение записывается в журнал приёмки вместе с причиной.

### Журнал приёмки

Каждый запуск добавляет строку. Прежние строки не меняются.

Приёмка 2026-10-18 шла в одноразовом клоне `/tmp/chebu-tutor-acceptance` на `origin/main` `463ce91` с навыком 0.1.0 из коммита `24d1868`. Синтетический `SESSION.md` с режимом `execute` и тикетом EDU-06 прошёл `handoff.py check` и восстанавливался перед каждым случаем. Случай H шёл в папке `/tmp/chebu-tutor-outside`: `git init`, копия адаптера в `.claude/skills/chebu-tutor/` и ссылка `.agents/skills/chebu-tutor`, без `AGENTS.md` и `.handoff/`. Список разрешал `python3`, чтение Git, `ls`, `cat`, `mkdir`, `cp`, `date` и инструменты чтения и записи файлов. Разговор продолжал ключ `--resume <id сессии>`. До и после случая снимались `git status --short --branch` и список файлов новее метки времени, включая игнорируемые. Модель во всех вызовах `claude-opus-5-5[1m]`.

Codex запускался командой `codex exec --json -c 'sandbox_mode="workspace-write"' -c 'approval_policy="never"' '$chebu-tutor <флаги>'`, разговор продолжала команда `codex exec resume <id>`. Модель взята из конфигурации Codex, вывод `--json` её не называет. В случае A ещё стояли ключи `sandbox_workspace_write.exclude_slash_tmp=true` и `sandbox_workspace_write.exclude_tmpdir_env_var=true`. С ними zsh не смог создать временный файл heredoc, поэтому остальные случаи шли с корнями записи Codex по умолчанию.

Cursor запускался командой `cursor-agent -p --output-format stream-json --trust --force --sandbox enabled '/chebu-tutor <флаги>'`, разговор продолжал ключ `--resume <id>`. Модель по выводу `init`: `Grok 4.7 500K Extra High`. Cursor обновился сам во время случая A: папка версии `2026.10.16-e3cb207` появилась в 17:28:13Z, поэтому A шёл на 2026.10.14-941492e, остальные случаи на 2026.10.16-e3cb207. Cursor не подставляет `$ARGUMENTS`. Во всех случаях из клона модель заменяла плейсхолдер словами из сообщения вызова, как требует D-13.

Devin 3000.11.92 запускался командой `devin --sandbox --respect-workspace-trust false --export <файл> -p '/chebu-tutor <флаги>'`, разговор продолжал ключ `-r <id сессии>`. Модель по экспорту: `DeepSeek V4.1 Flash Max`. Вместо сообщения вызова модель получает тело навыка с подставленным `$ARGUMENTS`. С ключом `--sandbox` Devin включает автономный режим прав, в котором инструменты `edit` и `write` ждут подтверждения, а без интерфейса подтверждение отклоняется. Песочница Devin ограничивает запись, но не чтение.

Код проверяет только то слово, которое ему передала модель, а строка `Режим тьютора:` возвращает его обратно. Поэтому шаг 2 теперь требует передать строку между разделителями без изменений. После команды модель сравнивает id в строке режима с флагом из слов вызова и при расхождении повторяет команду (D-30).

С текстом на `36c3bcb` Devin прошёл случай E. OpenCode 2.0.32 нарушил ENF-107 иначе: модель вызвала `start` без `--mode` в одном ходе с чтением SKILL.md, ещё не видя навыка. ENF-107 нарушено в двух рантаймах, поэтому правило перенесено ближе к коду (D-31). Шаг 1 «Начни сессию» AGENTS.md теперь сам отсылает вызов навыка к SKILL.md, а `start` без `--mode` последней строкой напоминает о команде проверки.

Наблюдение без нарушения контракта. Во всех восьми новых разговорах Claude Code модель первой попыткой собрала составную команду. В семи случаях из клона она дописала к команде проверки `echo "exit=$?"`, в случае H объединила проверку шага 1 в одну команду с переменной. Список разрешений отклонял такую команду, и модель повторяла её в том виде, в каком её задаёт навык. Проект не задаёт правил разрешений, поэтому в интерфейсе ученик и так подтверждает команду проверки, и `echo` попадает в тот же запрос. Отдельный запрос появится, если ученик разрешил `python3 .handoff/handoff.py` навсегда.
