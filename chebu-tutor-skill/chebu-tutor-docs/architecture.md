# Устройство навыка chebu-tutor

Документ объясняет, из чего состоит навык, почему он устроен именно так и какие варианты отвергнуты. Этапы 2–4 создали каталог навыка из раскладки ниже, этап 5 записал адаптеры в каталоги рантаймов.

## Навык тонкий

Правила тьютора уже записаны в [AGENTS.md](../../AGENTS.md), [tutor-modes.md](../../coding-agent-developement/tutor-modes.md) и [протоколе передачи сессии](../../.handoff/README.md). Их одинаково читают шесть рантаймов. Копия этих правил внутри навыка разошлась бы с оригиналом после первой правки, и рантаймы начали бы вести сессию по-разному.

Поэтому навык делает три вещи и только их:

1. Принимает флаг режима и проверяет его.
2. Запускает существующее начало сессии: `handoff.py start --runtime <id>`, протокол, снимок.
3. Направляет агента в раздел режима tutor-modes.md и дальше работает по AGENTS.md.

Цена решения: навык работает только в клоне `chebupelka-jev`, где эти файлы есть. Владелец принял эту цену (решение D-02).

## Один текст, два каталога

Все шесть рантаймов понимают формат Agent Skills: папка с файлом `SKILL.md`, в заголовке которого есть `name` и `description`. Различаются каталоги, в которых рантаймы ищут навыки проекта. По фактам [runtime-adapters.md](runtime-adapters.md) ни один каталог не читают все шесть, а пара каталогов покрывает всех:

| Каталог | Читают |
|---|---|
| `.claude/skills/chebu-tutor/SKILL.md` | `claude`, `cursor`, `devin`, `grok`, `opencode` |
| `.agents/skills/chebu-tutor/SKILL.md` | `codex`, `cursor`, `devin`, `grok`, `opencode` |

Поэтому навык ставится в оба каталога с одинаковым текстом. Файл лежит в `.claude/skills/chebu-tutor/`, а `.agents/skills/chebu-tutor` является символической ссылкой на `../../.claude/skills/chebu-tutor`. Проба этапа 1 показала, что копию Devin видит дважды, а ссылку один раз (решения D-10 и D-12).

Текст навыка пишется один раз в `chebu-tutor-skill/source/SKILL.md`. Генератор подставляет в него версию и записывает адаптеры:

```text
.handoff/TEMPLATE.md            id режимов
runtime-config/manifest.json    список рантаймов
runtime-config/runtimes/*.json  блок skill: папка адаптера или ссылка на неё
chebu-tutor-skill/skill.json    имя, версия, требования
chebu-tutor-skill/source/       папка навыка: SKILL.md и agents/openai.yaml
        |
        v
chebu-tutor-skill/tools/sync.py
        |
        +-- без ключа: записывает адаптер по каждому различному пути
        |              из блоков skill
        |
        `-- --check: строит адаптеры в памяти и сравнивает с файлами;
                     при любом расхождении печатает файлы и выходит с кодом 1
```

Адаптер является сгенерированным файлом. Его поле `metadata.version` называет версию навыка, а первая строка тела говорит, что файл сгенерирован и вручную не правится. Ручная правка адаптера ловится проверкой `--check`.

Папка адаптера повторяет `source/`. Кроме `SKILL.md` в ней лежит `agents/openai.yaml`: этим файлом Codex запрещает модели вызывать навык самой (D-22). Первая строка YAML тоже говорит, что файл сгенерирован. Генератор запускает запись только для расхождений, поэтому повторный запуск ничего не меняет. Файлы и папки он не удаляет. Ссылку на месте файла адаптера и ссылку Codex с другим текстом он заменяет. Папку или файл на месте ссылки, ссылку или файл на месте папки адаптера и файл в папке адаптера, которого нет в `source/`, он называет и останавливается до первой записи (D-23). Файлы с именем на точку, например `.DS_Store`, генератор не учитывает ни в `source/`, ни в адаптере.

## Флаг ищется в `$ARGUMENTS` и в тексте вызова

Рантаймы передают аргументы навыку по-разному. У Claude Code первый аргумент `$0`, у Devin и OpenCode `$1`, у Cursor и Codex подстановки в навыке нет, а текст вызова остаётся в сообщении ученика. Канонический текст поэтому не опирается на позиционные подстановки. Он велит агенту взять слова из сообщения, которым ученик вызвал навык, и передать их коду проверки флага (решение D-11).

Проба этапа 1 уточнила правило. Devin заменяет сообщение вызова телом навыка с подставленным `$ARGUMENTS`, и флаг там виден только в подстановке. Поэтому канонический текст содержит `$ARGUMENTS` и велит брать слова из подставленного значения, а если плейсхолдер остался буквальным, из сообщения вызова (решение D-13).

## id рантайма называет агент

Один текст в двух каталогах читают разные рантаймы, поэтому вписать в него `--runtime claude` нельзя. Агент подставляет id своего рантайма сам, как уже требует шаг 1 «Начни сессию» в AGENTS.md. Ключ `--runtime` обязателен: у Devin нет переменной окружения, по которой `handoff.py` распознал бы рантайм.

## Структуры данных

Каждый факт хранится в одном месте. Проверка синхронизации сравнивает производные файлы с этими местами.

| Факт | Где хранится | Почему там |
|---|---|---|
| id режимов и флаги | Строка «Режим тьютора» в [TEMPLATE.md](../../.handoff/TEMPLATE.md) | `handoff.py` уже проверяет снимок по этому перечислению. Второй список разошёлся бы с первым |
| Список рантаймов | [manifest.json](../../runtime-config/manifest.json) | Им уже пользуются `handoff.py` и тесты |
| Папка адаптера для рантайма | Блок `skill` в `runtime-config/runtimes/<id>.json` | По [project-structure.md](../../coding-agent-developement/project-structure.md) факты о рантайме лежат в `runtime-config/`. `load_runtime` лишние ключи пропускает |
| Имя, версия, описание и требования навыка | `chebu-tutor-skill/skill.json` | Собственные факты навыка, которых нет больше нигде |
| Текст и файлы папки навыка | `chebu-tutor-skill/source/`: `SKILL.md` и `agents/openai.yaml` | Один текст для всех рантаймов. Запрет вызова моделью лежит в заголовке `SKILL.md`, а для Codex рядом, в своём файле |

Предлагаемая форма `skill.json`:

```json
{
  "schema": 1,
  "name": "chebu-tutor",
  "version": "0.1.0",
  "description": "Ведёт учебную сессию chebupelka-jev в режиме, заданном флагом",
  "requires": {
    "handoff_schema": 2,
    "chebu_min_version": "0.1.4"
  }
}
```

`handoff_schema` равен схеме снимка, которую задаёт TEMPLATE.md. `chebu_min_version` называет первый тег `chebu`, в котором есть AGENTS.md, режимы и `.handoff/`. Списка режимов и рантаймов в `skill.json` нет: они читаются из источников выше.

Блок `skill` в файле рантайма называет папку навыка, которую читает рантайм. Состав полей выбрал этап 4 (D-21). Пять рантаймов указывают одну папку:

```json
"skill": {
  "dir": ".claude/skills/chebu-tutor"
}
```

У Codex блок равен `{"dir": ".agents/skills/chebu-tutor", "link_to": ".claude/skills/chebu-tutor"}`. Поле `link_to` говорит, что `dir` является символической ссылкой на папку другого блока. Текст ссылки `../../.claude/skills/chebu-tutor` генератор вычисляет сам. `--check` падает, если на месте ссылки лежит обычная папка или файл или ссылка ведёт в другое место (D-12).

Генератор проверяет блоки при чтении. Неизвестное поле, абсолютный путь или `..` дают ошибку. Последняя часть пути равна имени навыка из `skill.json`. Блоки с одной папкой должны совпадать. `link_to` должен называть папку, которую генератор пишет. Поля `invoke` из D-06 в блоке нет: команду вызова не читают ни генератор, ни этапы 5–7, а синтаксис вызова записан в [runtime-adapters.md](runtime-adapters.md).

## Раскладка каталога

Раскладка после этапов 2–5:

```text
chebu-tutor-skill/
|-- README.md            назначение каталога и статус разработки
|-- CHANGELOG.md         история версий навыка (этап 2)
|-- skill.json           имя, версия, требования (этап 2)
|-- source/SKILL.md      канонический текст навыка (этап 3)
|-- source/agents/openai.yaml  запрет вызова моделью для Codex (этап 4)
|-- tools/sync.py        генератор адаптеров и проверка --check (этап 4)
|-- tests/               тесты skill.json, флага и синхронизации (этапы 2–4)
`-- chebu-tutor-docs/    этот пакет документации

.claude/skills/chebu-tutor/SKILL.md               адаптер (этап 5)
.claude/skills/chebu-tutor/agents/openai.yaml     адаптер политики Codex (этап 5)
.agents/skills/chebu-tutor                        ссылка на ../../.claude/skills/chebu-tutor (этап 5)
```

Адаптеры отслеживаются в Git: новый clone должен получить работающую команду без установки. Правило `/.claude/worktrees/` в `.gitignore` каталог `.claude/skills/` не исключает. Git хранит ссылку как ссылку. На Windows без `core.symlinks` она станет текстовым файлом с путём, и Codex навык не найдёт. Машин с Windows в проекте пока нет.

## Проверка флага в коде

Разбор флага считается и проверяется да-нет, поэтому его исполняет код, а не текст инструкции (правило ENF-001 в [контракте](contract.md)). Есть два места для этого кода. Этап 3 выбирает одно и записывает решение в журнал.

| Вариант | Плюс | Минус |
|---|---|---|
| Ключ `--mode` у `handoff.py start`, слова вызова на stdin | Один скрипт. Проверка опирается на уже существующий разбор перечислений шаблона. Флаг проверяется до брифинга: при отказе команда печатает в stderr причину и строку использования и выходит с кодом 2. При успехе строка режима в выводе `start` сравнивает флаг с режимом из снимка | Меняется скрипт протокола, которым пользуются и сессии без навыка. Нужны новые тесты в `test_handoff.py` |
| Отдельный `chebu-tutor-skill/tools/mode.py` | Протокол не меняется | Второй скрипт с собственным чтением шаблона. Агенту нужно запустить две команды вместо одной |

Рекомендация: ключ `--mode` у `handoff.py start`. Он не меняет поведение без ключа, а перечисление режимов остаётся в одном парсере. Владелец выбрал этот вариант (D-16). Интерфейс команды описывает раздел «Разбор аргументов» [контракта](contract.md#разбор-аргументов).
