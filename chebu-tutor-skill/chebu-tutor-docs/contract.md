# Контракт навыка chebu-tutor

Контракт описывает, что делает навык после вызова. Этап 3 написал по нему канонический текст навыка, этап 5 записал адаптеры в каталоги рантаймов. Поведение в шести рантаймах проверяет матрица приёмки из [verification.md](verification.md). Изменение контракта до выпуска записывается в [журнал решений](architecture.md#журнал-решений), после выпуска оно требует новой версии по [правилам версий](versioning.md).

## Вызов

```text
/chebu-tutor --<режим> [текст ученика]
```

Ученик вызывает навык командой внутри открытого рантайма. Команда принимает не больше одного флага режима:

| Флаг | Режим | Кто меняет код тикета | Куда пишет агент |
|---|---|---|---|
| `--execute` | `execute` | Агент, по согласованному плану | Файлы проекта и состояние `.handoff/` |
| `--guide` | `guide` | Ученик | Только состояние `.handoff/` |
| `--walkthrough` | `walkthrough` | Никто | Только состояние `.handoff/` |
| `--sandbox` | `sandbox` | Никто | `.sandbox/` и состояние `.handoff/` |
| `--quiz` | `quiz` | Никто | Только состояние `.handoff/` |

Таблица повторяет раздел «Пять режимов» [tutor-modes.md](../../coding-agent-developement/tutor-modes.md). Флаги образуются из перечисления «Режим тьютора» в [TEMPLATE.md](../../.handoff/TEMPLATE.md), поэтому новый режим в шаблоне требует нового флага и новой версии навыка.

Текст после флага остаётся словами ученика: цель, тикет, ограничения. Его смысл задаёт раздел «Как начать сессию» в tutor-modes.md. Примеры:

```text
/chebu-tutor --guide тикет EDU-02, код пишу сам. DeepSeek не запускать.
/chebu-tutor --walkthrough разберём agent_loop() в agent/chebu.py
/chebu-tutor --quiz
```

В пяти рантаймах навык вызывается через `/`. В Codex навык упоминается через `$`: `$chebu-tutor --guide`. Команды вызова в каждом рантайме описывает [runtime-adapters.md](runtime-adapters.md).

Рантаймы передают аргументы навыку по-разному. Cursor не подставляет их вовсе, а Devin вместо сообщения вызова передаёт модели тело навыка с подставленным `$ARGUMENTS`. Поэтому текст навыка содержит `$ARGUMENTS`, и флаг берётся из подставленного значения. Если плейсхолдер остался буквальным, флаг берётся из сообщения, которым ученик вызвал навык (решения D-11 и D-13 в [журнале](architecture.md#журнал-решений)). Наблюдения по каждому рантайму записаны в [журнале проб](runtime-adapters.md#журнал-проб).

## Разбор аргументов

Слово, которое начинается с `--`, считается флагом. Остальные слова считаются текстом ученика.

| Аргументы | Поведение |
|---|---|
| Ровно один флаг из пяти | Режим равен флагу. Навык продолжает по разделу «Последовательность» |
| Флага нет | Навык печатает строку использования и начинает сессию как по фразе «Начни учебную сессию»: режим из снимка, а если его нет, таблица режимов и один вопрос |
| Два флага или больше | Отказ до брифинга: строка использования. Брифинг `start` не печатается, снимок не читается, файлы не меняются |
| Флаг вне списка, например `--exec` или `--help` | Отказ: строка использования с пятью флагами. Работа не начинается |
| Слово `$ARGUMENTS`: рантайм не подставил аргументы, а агент не заменил плейсхолдер | Отказ. Агент заменяет плейсхолдер словами из сообщения вызова и повторяет команду (D-18) |

Строка использования одна для всех рантаймов. Префикс `/` или `$` в неё не входит, потому что зависит от рантайма:

```text
использование: chebu-tutor --execute|--guide|--walkthrough|--sandbox|--quiz [цель, тикет, ограничения]
```

Поведение без флага владелец подтвердил решением D-15.

### Команда проверки

Таблицу разбора исполняет `handoff.py start` с ключом `--mode` (решение D-16). Слова вызова идут на stdin через heredoc. Разделитель в одинарных кавычках, поэтому shell не раскрывает в тексте ученика `$`, обратные кавычки и кавычки:

```bash
python3 .handoff/handoff.py start --runtime <id> --mode <<'CHEBU_TUTOR_ARGS'
--guide тикет EDU-02, код пишу сам
CHEBU_TUTOR_ARGS
```

Код делит stdin на слова по пробелам и переводам строк. Флаги строятся из перечисления «Режим тьютора» в TEMPLATE.md: `--` и id режима.

| Исход разбора | Код выхода | stdout | stderr |
|---|---|---|---|
| Ровно один флаг из списка | 0 | Брифинг `start`. Строка режима сравнивает флаг с режимом снимка | Пусто |
| Флага нет | 0 | Строка использования, затем брифинг `start` без изменений | Пусто |
| Два флага или больше | 2 | Пусто | Причина и строка использования |
| Флаг вне списка | 2 | Пусто | Причина и строка использования |
| Осталось слово `$ARGUMENTS` | 2 | Пусто | Причина и строка использования |

Без ключа `--mode` команда stdin не читает. Последней строкой она напоминает, что после вызова навыка нужна команда проверки с ключом `--mode` (D-31).

## Последовательность

1. Проверь, что текущая папка является клоном `chebupelka-jev`: в корне Git есть `AGENTS.md` и `.handoff/handoff.py`. Если их нет, сообщи «навык chebu-tutor работает только в клоне chebupelka-jev» и остановись.
2. Возьми слова из подставленного значения `$ARGUMENTS`. Если в тексте навыка `$ARGUMENTS` остался буквальным, возьми их из сообщения, которым ученик вызвал навык. Разбери слова кодом проверки по таблице выше. Проверка встроена в `handoff.py start --mode`, поэтому шаги 2 и 4 выполняет одна команда, а при отказе она не печатает брифинг.
3. Если в этом разговоре сессия уже начата, флаг означает смену режима, а вызов без флага режим не меняет. Подтверди смену одной строкой, сравнив флаг с текущим режимом разговора, и продолжай по правилам нового режима. Шаги 4–7 не повторяй (D-19).
4. Выполни из корня рабочей копии `python3 .handoff/handoff.py start --runtime <id>`. Агент подставляет id своего рантайма сам: один текст навыка читают разные рантаймы. С версии 0.1.1 текст навыка перечисляет id и говорит, что команда проверки заменяет шаг 1 «Начни сессию» AGENTS.md (ENF-107, D-29).
5. Прочитай раздел протокола, который назвала команда, затем снимок.
6. Сравни флаг с режимом из строки `Режим тьютора:` вывода `start`. Если они совпадают, назови режим. Если различаются или режима в снимке нет, назови режим из флага и подтверди смену одной строкой. Флаг важнее снимка.
7. Прочитай раздел режима в tutor-modes.md. Перепроверь Git и тикет по шагу 3 AGENTS.md. Объясни ученику состояние, расхождения со снимком и одно следующее действие.
8. Жди, пока ученик назовёт задачу и согласует план. До этого файлы проекта остаются без изменений.
9. Работай по правилам режима.
10. По фразе «закрой сессию» закрой сессию по AGENTS.md. В снимок попадает режим, действующий на момент закрытия.

## Что флаг не меняет

- Флаг не даёт разрешений. Платный запрос к DeepSeek, коммит, push, PR, тег, изменение issues и Project по-прежнему требуют слов ученика в текущей сессии.
- Флаг не отменяет начало по AGENTS.md. Состояние объясняется, план согласуется до работы.
- Флаг не пишет в снимок сам. Режим попадает в снимок при закрытии сессии через `handoff.py save`.
- Флаг не выбирает тикет и не задаёт цель. Их называет текст ученика или следующий ответ.

## Сообщения навыка

| Ситуация | Что видит ученик | Что дальше |
|---|---|---|
| Вызов вне клона | `навык chebu-tutor работает только в клоне chebupelka-jev` | Работа не начинается |
| Два флага или больше | `ошибка: нужен один флаг режима, получено <число>: <флаги>.`, затем строка использования | Работа не начинается |
| Флаг вне списка | `ошибка: флаг <флаг> не входит в список режимов.`, затем строка использования | Работа не начинается |
| Осталось слово `$ARGUMENTS` | `ошибка: в словах вызова осталось $ARGUMENTS: замени его словами, с которыми ученик вызвал навык.`, затем строка использования | Агент повторяет команду со словами из сообщения вызова |
| Флаг в начатой сессии | `Режим тьютора: <новый id> по флагу, был <текущий id>` | Сессия продолжается в новом режиме. Строку строит агент |
| Вызов без флага в начатой сессии | Режим не меняется | Сессия продолжается |
| Флага нет | Строка использования, затем брифинг `start` | Сессия начинается с режимом из снимка |
| `start` завершился с кодом 2 из-за рантайма | Сообщение `start` со списком известных id | Агент повторяет команду с id своего рантайма |
| Флаг совпал с режимом снимка | `Режим тьютора: <id>, из снимка и флага` | Сессия продолжается |
| Флаг отличается от режима снимка | `Режим тьютора: <новый id> по флагу, в снимке был <старый id>` | Сессия продолжается в новом режиме |
| Снимка нет или в нём нет режима | `Режим тьютора: <id> по флагу, в снимке режима нет` | Сессия продолжается в режиме флага |

Тексты зафиксированы на этапе 3. Строки с `ошибка:`, строку использования и строки `Режим тьютора:` печатает `handoff.py start --mode`, их проверяет класс `ModeTest` в [test_handoff.py](../../.handoff/test_handoff.py). Сообщение о вызове вне клона и строку смены режима в начатой сессии произносит агент по тексту навыка.

## Правила навыка по способу исполнения

Правило, которое можно посчитать или проверить да-нет, исполняет код. Правило, которое можно сформулировать как инструкцию, исполняет текст навыка. Правило, которому нужно суждение, остаётся за моделью. Номера ENF-001–099 закреплены за кодом, ENF-100–199 за инструкциями, ENF-200–299 за моделью.

| ID | Правило | Исполнение | Чем проверяется |
|---|---|---|---|
| ENF-001 | Ровно один флаг из пяти, иначе отказ до брифинга: строк `Рантайм:` и `Снимок:` в выводе нет | Код: ключ `--mode` у `handoff.py start` (D-16) | Модульные тесты на каждую строку таблицы разбора |
| ENF-002 | Список флагов равен перечислению «Режим тьютора» в TEMPLATE.md | Код: проверка синхронизации | Тест, который меняет перечисление в копии шаблона и ждёт отказа |
| ENF-003 | Адаптеры совпадают с каноническим источником и несут одну версию | Код: `sync.py --check` | Тест, который меняет адаптер и ждёт отказа с именем файла |
| ENF-004 | Сессия начинается командой `handoff.py start` с ключом `--runtime` | Код скрипта и инструкция навыка | Строка `Рантайм: ...` в выводе на приёмке |
| ENF-005 | Снимок сохраняется только после проверки | Код: `handoff.py save` | Существующие тесты `.handoff` |
| ENF-006 | Навык работает только в клоне | Код: проверка файлов на шаге 1 | Вызов из папки вне клона на приёмке |
| ENF-101 | Флаг важнее режима снимка, смена подтверждается одной строкой | Инструкция | Матрица приёмки, строки «флаг отличается от снимка» |
| ENF-102 | До согласования плана файлы проекта не меняются | Инструкция | `git status --short` до вызова и после первого ответа |
| ENF-103 | Граница записи режима | Инструкция | `git status --short` до шага и после него |
| ENF-104 | Флаг не даёт разрешений | Инструкция | Вызов с флагом без разрешения: платного запуска и публикации нет |
| ENF-105 | В `quiz` ответ не раскрывается до ответа ученика | Инструкция | Матрица приёмки, строка `--quiz` |
| ENF-106 | В `guide` подсказки идут по уровням и только по просьбе | Инструкция | Матрица приёмки, строка `--guide`, уровень подсказки в снимке |
| ENF-107 | Первая команда после вызова навыка — команда проверки `start --mode`. Команда `start` без ключа `--mode` не выполняется | Инструкция: шаг 2 навыка называет id рантаймов и заменяет шаг 1 «Начни сессию» AGENTS.md (D-29). Шаг 1 AGENTS.md сам отсылает вызов навыка к SKILL.md. Код: `start` без `--mode` последней строкой отсылает к команде проверки (D-31) | Вывод первой команды содержит строку `Режим тьютора:` со словами `по флагу` или `из снимка и флага` |
| ENF-108 | Строка между разделителями равна словам вызова: флаг ученика не меняется | Инструкция: шаг 2 навыка требует передать строку без изменений и сверить id в строке `Режим тьютора:` с флагом из слов вызова (D-30) | Строка `Режим тьютора:` в выводе первой команды называет id из флага вызова |
| ENF-201 | Качество объяснения, выбор вопроса, формулировка шага | Модель | Оценка владельца на приёмке |

Если инструкция нарушена на приёмке, нарушение записывается в [verification.md](verification.md) вместе с рантаймом и версией навыка. Повторное нарушение одного правила в двух рантаймах означает, что правило надо перевести ближе к коду: сократить текст, вынести проверку в скрипт или добавить пример в канонический источник.
