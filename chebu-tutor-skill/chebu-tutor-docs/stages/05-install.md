# Этап 5. Адаптеры в рантаймах и документы проекта

## Цель

Записать адаптеры в настоящее дерево и связать навык с документами проекта. После этапа новый clone получает команду `/chebu-tutor` во всех шести рантаймах без установки, а ученик находит её описание из tutor-modes.md.

## Входные условия

| Условие | Команда | Ожидаемый результат |
|---|---|---|
| Этап 4 готов | Строка этапа 4 в [progress.md](../progress.md) | Статус «Готово» |
| Рабочее дерево чистое | `git status --short` | Пустой вывод |
| Тесты зелёные | Тесты навыка и `.handoff` | `OK` в обоих |

## Прочитать

- [runtime-adapters.md](../runtime-adapters.md): пути адаптеров.
- [contract.md](../contract.md), раздел «Вызов».
- [project-structure.md](../../../coding-agent-developement/project-structure.md), разделы 3, 4 и 9.
- [tutor-modes.md](../../../coding-agent-developement/tutor-modes.md), раздел «Как начать сессию: промпты для ученика».

## Шаги

1. Выполни `python3 chebu-tutor-skill/tools/sync.py`. Сравни список записанных файлов с путями из блоков `skill`.
2. Выполни `python3 chebu-tutor-skill/tools/sync.py --check`. Ожидаемый код выхода 0.
3. Проверь, что Git не игнорирует адаптеры: `git check-ignore <путь>` для каждого пути должен завершиться кодом 1.
4. Добавь в раздел 4 project-structure.md строки для канонического текста, генератора и каталогов адаптеров. Обнови дерево раздела 3 и добавь строку в журнал раздела 9.
5. Добавь в раздел «Как начать сессию: промпты для ученика» tutor-modes.md подраздел о вызове `/chebu-tutor --<режим>`: таблица флагов и ссылка на контракт.
6. Добавь строку в таблицу «Куда смотреть» AGENTS.md и в навигацию корневого README.
7. Обнови `chebu-tutor-skill/README.md`: навык установлен, выпуск ещё не сделан.
8. Если владелец разрешил запуск, вызови `/chebu-tutor --walkthrough` в Claude Code в основном клоне и проверь, что `git status --short` после первого ответа не изменился.

## Критерий готовности

- `python3 chebu-tutor-skill/tools/sync.py --check` завершается кодом 0.
- `git status --short` показывает адаптеры ровно по путям из блоков `skill` и изменённые документы.
- Тесты навыка и `.handoff` завершаются `OK`.
- Относительные ссылки в изменённых документах ведут к существующим файлам.

## Что записать

- Строку этапа 5 в [progress.md](../progress.md).
- Запись в `[Unreleased]` CHANGELOG навыка и строку в `[Unreleased]` CHANGELOG проекта.
- Итог пробного вызова шага 8 или пометку «не запускался».

## Границы

- Адаптеры не правятся вручную. Любое изменение идёт через источник и `sync.py`.
- Версия остаётся `0.1.0`, тег не создаётся.
- Документы не называют навык выпущенным до этапа 7.
- Коммит, push и PR только по разрешению владельца в текущей сессии.
