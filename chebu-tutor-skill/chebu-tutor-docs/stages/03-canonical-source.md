# Этап 3. Канонический текст и проверка флага

## Цель

Сделать два элемента навыка, которые одинаковы для всех рантаймов. Первый: код, который разбирает аргументы и проверяет флаг (правило ENF-001 [контракта](../contract.md)). Второй: канонический текст `chebu-tutor-skill/source/SKILL.md`, по которому этап 4 построит адаптеры.

| Этап 2 готов | Строка этапа 2 в [progress.md](../progress.md) | Статус «Готово» |

## Шаги

1. Задай владельцу вопросы D-08 и D-09. Запиши ответы строками журнала в [architecture.md](../architecture.md). Если ответ совпал с предложением, строка подтверждает прежнее решение.
2. Определи интерфейс проверки. Вход: слова из подставленного значения `$ARGUMENTS`, а если плейсхолдер остался буквальным, из сообщения, которым ученик вызвал навык (решения D-11 и D-13). Текст ученика не должен проходить через интерпретацию shell: передавай его на stdin через heredoc в одинарных кавычках или передавай только слова-флаги. Выход: id режима, строка использования или отказ. Код выхода 2 означает отказ. Запиши интерфейс в раздел «Разбор аргументов» контракта.
3. Напиши тесты до кода по строкам этапа 3 в verification.md. Если выбран ключ `--mode` у `handoff.py start`, тесты идут в [test_handoff.py](../../../.handoff/test_handoff.py). Если выбран отдельный скрипт, тесты идут в `chebu-tutor-skill/tests/`.
4. Запусти тесты. Новые тесты должны упасть по ожидаемой причине: проверки ещё нет.
5. Напиши минимальный код. Список режимов читается из перечисления «Режим тьютора» в TEMPLATE.md тем же разбором, что в `handoff.py`. Запусти тесты до зелёного итога.
6. Внеси дефект: код принимает `--exec`. Тест неизвестного флага должен упасть. Процитируй сообщение и верни код.
7. Напиши `chebu-tutor-skill/source/SKILL.md` в формате Agent Skills. Заголовок содержит `name: chebu-tutor`, `description`, подстановку версии в `metadata.version` и поле, которое запрещает агенту вызывать навык без ученика. Выбор поля опирается на следствие 6 в runtime-adapters.md, поле `user-invocable: false` ставить нельзя. Тело повторяет «Последовательность» контракта короткими инструкциями и ссылается на AGENTS.md, tutor-modes.md и команды `handoff.py`, а не пересказывает их. Тело содержит `$ARGUMENTS` одной строкой там, где агент берёт слова для проверки флага (D-13). Синтаксис подстановки версии, например `{{version}}`, фиксируется здесь: этап 4 его использует. id рантайма не подставляется: один текст читают разные рантаймы, и агент называет id сам (D-11).
8. Напиши тест содержания: источник ссылается на `AGENTS.md`, `tutor-modes.md` и `.handoff/handoff.py start`, содержит `$ARGUMENTS` и строку использования, равную строке в контракте, и называет каждый флаг из перечисления.
9. Обнови таблицу «Сообщения навыка» контракта точными текстами.

## Критерий готовности

- Тесты навыка завершаются `OK`.
- Тесты `.handoff` завершаются `OK`. Если менялся `handoff.py`, прежние 63 теста проходят без изменений, а новые добавлены.
- Дефект `--exec` дал падение, сообщение процитировано.
- `chebu-tutor-skill/source/SKILL.md` существует, тест содержания проходит.
- `git status --short` не показывает файлов в каталогах рантаймов из runtime-adapters.md.

## Границы

- Генератор и адаптеры на этом этапе не создаются.
- Поведение `handoff.py start` без нового ключа не меняется.
- Текст навыка не копирует правила AGENTS.md и tutor-modes.md.
- Версия остаётся `0.1.0`.
- Коммит, push и PR только по разрешению владельца в текущей сессии.
