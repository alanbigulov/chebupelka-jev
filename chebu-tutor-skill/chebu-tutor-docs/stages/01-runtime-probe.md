# Этап 1. Пробный навык в шести рантаймах

## Цель

Подтвердить наблюдением, что каждый из шести рантаймов находит навык проекта в `.claude/skills/` или `.agents/skills/` и что текст вызова `--guide` вместе со словами ученика доходит до агента без изменений. Весь замысел навыка держится на этом факте, поэтому этап идёт первым. Результат этапа: метки `confirmed-local` в [runtime-adapters.md](../runtime-adapters.md) вместо меток из документации и догадок.

Проба одноразовая. Файлы пробного навыка живут только в одноразовом клоне и в Git не попадают.

## Входные условия

| Условие | Команда | Ожидаемый результат |
|---|---|---|
| Пакет документации слит в `main` | `git fetch origin`, затем `git log --oneline -1 origin/main -- chebu-tutor-skill/chebu-tutor-docs/README.md` | Печатается коммит |
| Рабочее дерево чистое | `git status --short` | Пустой вывод |
| Владелец разрешил запуски рантаймов в текущей сессии | Вопрос владельцу | Названы рантаймы и число запусков |
| CLI установлены | `claude --version`, `codex --version`, `cursor-agent --version`, `devin --version`, `grok --version`, `opencode --version` | Каждая команда печатает версию |

## Прочитать

- [verification.md](../verification.md), раздел «Подготовка».
- [architecture.md](../architecture.md), раздел «Один текст, два каталога».

## Шаги

1. Создай одноразовый клон: `git clone https://github.com/alanbigulov/chebupelka-jev.git /tmp/chebu-tutor-probe`. Дальнейшие файлы пробы создавай только в нём.
2. Создай пробный навык `.claude/skills/chebu-tutor-probe/SKILL.md` в формате Agent Skills. Заголовок: `name: chebu-tutor-probe`, `description`, `metadata` с ключом `version: 0.0.0`. Текст: «Напечатай одной строкой `PROBE` и полный текст сообщения, которым тебя вызвали, без изменений. Затем напечатай строку `ARGS` и значение $ARGUMENTS. Больше ничего не делай: команды не запускай, файлы не меняй».
3. Вариант «копия»: скопируй папку в `.agents/skills/chebu-tutor-probe/`.
4. Интерактивные вызовы делает владелец: сессия Claude Code не управляет интерфейсом другого рантайма. Попроси владельца открыть каждый рантайм в `/tmp/chebu-tutor-probe`, вызвать навык командой из таблицы «Вызов и аргументы» runtime-adapters.md с именем `chebu-tutor-probe` вместо `chebu-tutor` и текстом `--guide тикет "EDU-02" $HOME`, затем вставить вывод в чат. Вызовы без интерфейса из той же таблицы ты запускаешь сам из `/tmp/chebu-tutor-probe`, только в рантаймах и в числе, которые разрешил владелец.
5. Для каждого рантайма запиши ответы на вопросы 1–5 раздела «Открытые вопросы для этапа 1» runtime-adapters.md: сколько раз навык виден в списке или подсказке, как дошёл текст вызова, раскрылся ли `$ARGUMENTS`, остался ли `$HOME` текстом, не помешало ли поле `metadata`.
6. Вариант «ссылка»: в `/tmp/chebu-tutor-probe` удали копию командой `rm -rf .agents/skills/chebu-tutor-probe`, затем создай ссылку `ln -s ../../.claude/skills/chebu-tutor-probe .agents/skills/chebu-tutor-probe`. Повтори шаги 4 и 5 в рантаймах, которые читают оба каталога: Cursor, Devin, Grok, OpenCode, а также в Codex.
7. Вопрос 6 закрывается по выводу рантайма о загруженных файлах правил, если рантайм такой вывод показывает. Вопрос 7 требует отдельной настройки. Создай в пробном клоне worktree: `git -C /tmp/chebu-tutor-probe worktree add /tmp/chebu-tutor-probe-wt`. Положи в его `.handoff/` синтетический `SESSION.next.md` по разделу «Подготовка» verification.md. Попроси владельца запустить в `/tmp/chebu-tutor-probe-wt` Codex в режиме `workspace-write` с задачей выполнить `python3 .handoff/handoff.py save`. Итог вопроса: появился ли файл `/tmp/chebu-tutor-probe/.handoff/SESSION.md`. Если владелец отказался от запуска, отметь вопрос «Не проверено» с причиной.
8. Добавь в журнал проб runtime-adapters.md строку на каждый вызов. Для итога «Проверено» замени метку факта в разделе рантайма на `confirmed-local` со ссылкой на дату пробы. Неподтверждённый факт оставь с меткой и причиной. Выбери копию или ссылку для решения D-10 и запиши выбор новой строкой журнала решений.
9. Если рантайм не находит навык проекта или текст вызова до агента не доходит, остановись. Опиши владельцу наблюдение и варианты обхода. Решение D-01 меняет только владелец, и изменение записывается новой строкой журнала решений.
10. Удали одноразовые каталоги: `rm -rf /tmp/chebu-tutor-probe /tmp/chebu-tutor-probe-wt`.

## Критерий готовности

- Для каждого из шести рантаймов в журнале проб runtime-adapters.md есть строка с итогом «Проверено» или с итогом «Не проверено» и причиной.
- Для каждого рантайма с итогом «Проверено» записано, как дошёл текст `"EDU-02" $HOME` и сколько раз виден навык в вариантах «копия» и «ссылка».
- В журнале решений architecture.md есть строка, которая выбирает копию или ссылку для D-10.
- `git status --short` в рабочей копии этапа показывает только изменения в `chebu-tutor-skill/chebu-tutor-docs/`.
- Одноразовых каталогов нет: `ls /tmp/chebu-tutor-probe /tmp/chebu-tutor-probe-wt` завершается ошибкой для обоих.

## Что записать

- Статус «Готово» этапу 0 в [progress.md](../progress.md) со ссылкой на слитый PR пакета: входное условие это уже подтвердило.
- Строку этапа 1 в progress.md: статус, рантаймы с итогом, дата.
- Новые факты в runtime-adapters.md с метками.
- Строку журнала решений в [architecture.md](../architecture.md), если проба меняет контракт или раскладку адаптеров.

## Границы

- Пробный навык не попадает в основной клон и в Git.
- `skill.json`, канонический текст, генератор и адаптеры на этом этапе не создаются.
- Каждый запуск рантайма идёт только в объёме разрешения владельца. Запрос к DeepSeek не нужен.
- Обход неподдерживаемого рантайма не выбирается без владельца.
- Коммит, push и PR только по разрешению владельца в текущей сессии.
