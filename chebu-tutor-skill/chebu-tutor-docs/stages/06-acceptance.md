# Этап 6. Приёмка в шести рантаймах

## Цель

Проверить наблюдением, что навык ведёт себя одинаково во всех шести рантаймах. Этап выполняет матрицу из [verification.md](../verification.md): девять случаев в каждом рантайме, 54 ячейки. Найденные расхождения исправляются до выпуска.

## Входные условия

| Условие | Команда | Ожидаемый результат |
|---|---|---|
| Этап 5 готов | Строка этапа 5 в [progress.md](../progress.md), затем `gh pr view 34 -R alanbigulov/chebupelka-jev` | «Готово», либо «Проверка» и PR в состоянии `MERGED` |
| Адаптеры этапа 5 в `main` | `git fetch origin`, затем `git log --oneline -1 origin/main -- .claude/skills/chebu-tutor/SKILL.md` | Печатается коммит |
| Адаптеры синхронны | `python3 chebu-tutor-skill/tools/sync.py --check` | Код выхода 0 |
| Владелец разрешил запуски | Вопрос владельцу | Названо число запусков, до 54 и повторы |

## Прочитать

- [verification.md](../verification.md), раздел «Ручная приёмка в рантаймах».
- [contract.md](../contract.md), разделы «Сообщения навыка» и «Правила навыка по способу исполнения».
- [runtime-adapters.md](../runtime-adapters.md): команды вызова.

## Шаги

1. Подготовь одноразовый клон по разделу «Подготовка» verification.md. Основной клон владельца приёмка не трогает.
2. Выполни случаи A–I в одном рантайме. Начни с Claude Code: в нём идёт разработка, и сбои там дешевле разбирать.
3. После каждого случая добавь строку в журнал приёмки verification.md: дата, версия навыка, рантайм и версия CLI, случай, команда, наблюдение, итог.
4. Повтори шаги 2 и 3 для остальных пяти рантаймов.
5. Каждое расхождение с контрактом запиши с номером правила ENF. Если одно правило нарушено в двух рантаймах, предложи владельцу перенести его ближе к коду.
6. Исправления делай в отдельной ветке через источник и `sync.py`, а не в одноразовом клоне. После слияния повтори затронутые ячейки.
7. Обнови в `runtime-config/runtimes/<id>.json` существующие поля `checked.date` и `checked.cli_version` и добавь в `checked.confirmed` строку о приёмке навыка. Состав блока `skill` этот этап не меняет: его задал этап 4.
8. Удали одноразовый клон.

## Критерий готовности

- В журнале приёмки 54 ячейки с итогом «Проверено» либо с исключением, которое владелец явно принял в сессии, с причиной.
- После последнего исправления `sync.py --check` завершается кодом 0, тесты навыка и `.handoff` завершаются `OK`.
- Одноразового клона нет.

## Что записать

- Статус «Готово» этапу 5 в [progress.md](../progress.md) со ссылкой на слитый PR #34, первым коммитом ветки.
- Строку этапа 6 в progress.md и статус «К выполнению» этапу 7.
- Журнал приёмки в verification.md.
- Запись в `[Unreleased]` CHANGELOG навыка о результатах приёмки.

## Границы

- Приёмка не меняет снимок владельца и основной клон.
- Запрос к DeepSeek не нужен.
- Исправление поведения не меняет контракт без строки журнала решений.
- Коммит, push и PR только по разрешению владельца в текущей сессии.
