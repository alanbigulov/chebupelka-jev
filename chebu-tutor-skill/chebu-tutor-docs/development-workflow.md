# Как вести сессию разработки навыка

Документ написан для сессии Claude Code, которая выполняет один этап разработки `chebu-tutor`, и для владельца, который такую сессию открывает. Разработку ведут только сессии Claude Code (решение D-05 в [журнале](architecture.md#журнал-решений)). Остальные пять рантаймов участвуют в этапах 1 и 6 как объекты проверки.

## Сессия разработки подчиняется AGENTS.md

Claude Code в этом репозитории всегда загружает [AGENTS.md](../../AGENTS.md) через [CLAUDE.md](../../CLAUDE.md). Отдельных правил для разработки нет: сессия разработки является обычной сессией по AGENTS.md.

| Понятие AGENTS.md | Значение в сессии разработки |
|---|---|
| Ученик | Владелец репозитория. Он принимает решения и даёт разрешения |
| Задача сессии | Один этап из каталога `stages/` |
| Режим тьютора | `execute`: агент меняет файлы по согласованному плану |
| Снимок `.handoff/` | Контекст сессии для продолжения в следующей сессии |
| [progress.md](progress.md) | Статус этапов. В отличие от снимка, лежит в Git |

## Промпт владельца

```text
Продолжи работу по AGENTS.md и .handoff/SESSION.md.
Моя цель на эту сессию: этап NN разработки навыка chebu-tutor по chebu-tutor-skill/chebu-tutor-docs/stages/NN-<имя>.md.
Режим на эту сессию: execute.
Особые ограничения: <например «коммит, push и PR разрешаю, тег нет»>.
```

Номер этапа владелец берёт из [progress.md](progress.md): первый этап со статусом «К выполнению».

## Порядок сессии

1. Начни сессию по AGENTS.md: `python3 .handoff/handoff.py start --runtime claude`, протокол, снимок, перепроверка Git.
2. Прочитай [индекс пакета](README.md), [progress.md](progress.md) и файл этапа. Затем прочитай документы из раздела «Прочитать» этапа.
3. Выполни команды раздела «Входные условия». Если хотя бы одно условие не выполнено, этап не начинай: назови владельцу условие и наблюдаемый результат.
4. Изолируй работу. Фоновая сессия создаёт git worktree инструментом `EnterWorktree` до первой правки. Интерактивная сессия в основном клоне создаёт ветку `chebu-tutor/stage-NN`.
5. Согласуй с владельцем план этапа. Если этап требует решения владельца, задай вопрос до работы.
6. Выполняй шаги по одному. После каждого шага запусти его проверку и покажи вывод. Следующий шаг начинай только после зелёной проверки.
7. Выполни все команды раздела «Критерий готовности» и процитируй их вывод. Этап готов, только если выполнен каждый пункт.
8. Сделай записи из раздела «Что записать»: строка в progress.md, решения в журнале architecture.md, запись в `chebu-tutor-skill/CHANGELOG.md` начиная с этапа 2.
9. Публикуй только в объёме разрешения: коммит, push, PR. Команда `gh` всегда получает `-R alanbigulov/chebupelka-jev`.
10. Закрой сессию по AGENTS.md: снимок и `handoff.py save`.

## Если этап не закончен

Остановись на наблюдаемой границе: законченный шаг или конкретный блокер. В progress.md поставь статус «В работе» или «Заблокировано» и перечисли оставшиеся шаги. Снимок `.handoff/` хранит детали сессии. Следующая сессия продолжает с первого невыполненного шага.

## Если документ расходится с репозиторием

Факты в [existing-rules.md](existing-rules.md) и [runtime-adapters.md](runtime-adapters.md) сняты 2026-10-15. Если файл или CLI ведёт себя иначе, верь наблюдению. Исправь документ в той же ветке, отметь новую дату и запиши расхождение в журнал решений.

## Необязательные skills Claude Code

Протокол выполняется без skills. Если они установлены, помогают такие:

| Skill | Где помогает |
|---|---|
| `pstack:poteto-mode` | Этапы с кодом: 2, 3, 4 |
| `pstack:tdd` | Тесты до кода на этапах 2, 3, 4 |
| `pstack:technical-writing`, `pstack:unslop` | Документы на этапах 5 и 7 |

Использованный skill называется в разделе «Необязательные skills» снимка.

## Известные ловушки репозитория

Наблюдались в сессиях 2026-10-13 и 2026-10-15.

| Ловушка | Что делать |
|---|---|
| `gh` без ключа `-R` обращается к `upstream`, репозиторию исходного автора | Всегда пиши `gh ... -R alanbigulov/chebupelka-jev` |
| Фоновая сессия в worktree не может писать в основной клон, в том числе в его `.handoff/` | Пиши `.handoff/SESSION.next.md` в worktree и выполняй `python3 .handoff/handoff.py save`. Скрипт перенесёт снимок |
| Bash изолированной сессии отклоняет составные команды со словом git: циклы, переменные, heredoc | Пиши простые команды с явными аргументами. Текст коммита и PR пиши в файл и передавай путь |
| После «Rebase and merge» коммиты ветки получают новые SHA, и `ExitWorktree` отказывается удалить worktree | Сравни деревья: `git rev-parse '<ветка>^{tree}' 'origin/main^{tree}'`. При совпадении удаляй с подтверждения владельца |
