# История изменений chebu-tutor

Здесь фиксируются существенные изменения навыка `chebu-tutor`. Номер версии хранит [skill.json](skill.json). Правила номеров, тегов и выпуска описаны в [versioning.md](chebu-tutor-docs/versioning.md). Изменения `chebu` ведёт [CHANGELOG.md](../CHANGELOG.md) проекта.

## [Unreleased]

Изменений после выпуска 0.1.1 нет.

## [0.1.1], 2026-10-19

Исправление для Devin, тег `chebu-tutor-v0.1.1`. Поведение по контракту не меняется.

### Исправления

- Вступление навыка говорит модели, что полученный текст навыка и есть вызов: Devin передаёт тело навыка вместо сообщения вызова. Шаг 2 сам перечисляет id рантаймов и говорит, что команда проверки заменяет шаг 1 «Начни сессию» AGENTS.md, а `start` без `--mode` не выполняется (D-29, ENF-107). С навыком 0.1.0 Devin 3000.11.92 в двух запусках выполнил `start` без `--mode`: модель шла за id рантайма в AGENTS.md.
- Шаг 2 требует передать строку между разделителями без изменений и сверить id в строке `Режим тьютора:` с флагом из слов вызова. При расхождении модель повторяет команду с исходной строкой (D-30, ENF-108). При первом повторе Devin с текстом 0.1.1 модель передала `--guide` вместо `--execute`.
- Тесты [test_source.py](tests/test_source.py) проверяют, что шаг 2 называет каждый id из `runtime-config/manifest.json`, запрещает `start` без `--mode`, требует передать строку без изменений и сверить флаг.

### Документация

- [README.md](README.md) навыка стал инструкцией для ученика: первая сессия за пять шагов, флаги, вызов в шести рантаймах, команды по ситуациям, разрешения, сообщения навыка, разбор ошибок и запасной промпт. Сведения для разработчиков собраны в разделе «Разработка навыка».
- Команда `/chebu-tutor --<режим>` стала способом начать сессию по умолчанию в [tutor-modes.md](../coding-agent-developement/tutor-modes.md) и корневом [README](../README.md). `handoff.py save` печатает команды продолжения с навыком. Промпт остался запасным путём для случаев без навыка.

### Приёмка

- Команды продолжения с навыком 0.1.0 проверены 2026-10-19 в основном клоне, строки в [журнале приёмки](chebu-tutor-docs/verification.md#журнал-приёмки). Claude Code 2.1.303, Codex 0.163.0, Cursor 2026.10.16-e3cb207, Grok 1.0.62 и OpenCode 2.0.32 первой командой выполнили проверку флага. Devin 3000.11.92 её пропустил дважды, это исправляет 0.1.1. Повтор Devin с промежуточным текстом 0.1.1 на `3884e70` выполнил проверку, но передал флаг `--guide` вместо `--execute`, это исправляет D-30. С текстом на `36c3bcb` Devin прошёл случай E. OpenCode 2.0.32 выполнил `start` без `--mode` в одном ходе с чтением SKILL.md и сам исправился, поэтому ENF-107 перенесено ближе к коду вне навыка (D-31). После этого OpenCode на `9bc037b` прошёл случай E, и у всех 54 ячеек матрицы последний итог «Проверено».

## [0.1.0], 2026-10-19

Первый выпуск навыка, тег `chebu-tutor-v0.1.0`. Ученик начинает сессию командой `/chebu-tutor --<режим>`, в Codex `$chebu-tutor --<режим>`, и агент ведёт её в режиме из флага. Навык работает в клоне `chebu` начиная с v0.1.4, со схемой снимка 2.

### Выпуск

- Чек-лист выпуска в [versioning.md](chebu-tutor-docs/versioning.md) ставит тег на коммит слияния PR выпуска в `main`, а не на коммит ветки: squash-слияние даёт коммиту новый SHA (D-28).

- Четыре ячейки один раз нарушили правило контракта и прошли при повторе: ENF-106 в случае C у Codex и Devin, ENF-105 и ENF-001 у Devin. ENF-106 нарушено в двух рантаймах. - Генератор записал адаптеры в настоящее дерево: `.claude/skills/chebu-tutor/SKILL.md`, `.claude/skills/chebu-tutor/agents/openai.yaml` и ссылку `.agents/skills/chebu-tutor` на `../../.claude/skills/chebu-tutor`. - [tutor-modes.md](../coding-agent-developement/tutor-modes.md) объясняет ученику вызов навыка: таблица флагов с примерами и ссылка на [контракт](chebu-tutor-docs/contract.md). На навык ссылаются AGENTS.md, корневой README и project-structure.md.

### Генератор адаптеров

- Добавлен [tools/sync.py](tools/sync.py). Без ключа он записывает адаптеры по блокам `skill` из `runtime-config/runtimes/`: папку `.claude/skills/chebu-tutor/` и символическую ссылку `.agents/skills/chebu-tutor` на неё. С ключом `--check` он ничего не пишет, называет каждый расходящийся путь и выходит с кодом 1. Расхождением считается и файл в папке адаптера, которого нет в `source/`. Повторный запуск ничего не меняет. Файлы и папки генератор не удаляет и через ссылки не пишет, а ссылку на месте файла адаптера или ссылку Codex с другим текстом заменяет. Папку или файл на месте ссылки, ссылку или файл на месте папки адаптера и лишний файл он называет и выходит с кодом 1 до первой записи.
- Папка адаптера повторяет [source/](source/). `SKILL.md` получает версию и описание из `skill.json` и пометку о генерации первой строкой тела. Добавлен [source/agents/openai.yaml](source/agents/openai.yaml) с `policy.allow_implicit_invocation: false`: Codex не вызывает навык сам, явный `$chebu-tutor` работает.
- Генератор проверяет, что источник называет каждый флаг из перечисления «Режим тьютора» [шаблона](../.handoff/TEMPLATE.md) и строку использования, которую печатает `handoff.py`.
- В каждый файл `runtime-config/runtimes/<id>.json` добавлен блок `skill`: папка навыка `dir`, у Codex ещё `link_to`.
- Добавлен 21 тест [test_sync.py](tests/test_sync.py). Каждый работает на временной копии дерева и ловит свой дефект: ручную правку адаптера, дрейф версии, рантайм без блока, повторную запись, запись вне путей блоков и через ссылку, копию вместо ссылки, лишний файл в адаптере, опечатку в блоке, новый режим.

### Проверка флага и канонический текст

- `python3 .handoff/handoff.py start --runtime <id> --mode` читает слова вызова навыка из stdin и проверяет флаг режима до брифинга. Два флага, флаг вне списка или неподставленный `$ARGUMENTS` дают отказ с кодом 2 и строкой использования. Без флага команда печатает строку использования и обычный брифинг. С флагом строка `Режим тьютора:` сравнивает флаг с режимом снимка. Флаги строятся из перечисления «Режим тьютора» в [шаблоне](../.handoff/TEMPLATE.md). Без ключа `--mode` команда работает как прежде.
- Добавлены 11 тестов `ModeTest` в [test_handoff.py](../.handoff/test_handoff.py).
- Добавлен канонический текст [source/SKILL.md](source/SKILL.md). Заголовок запрещает вызов моделью полями `disable-model-invocation` и `triggers`. Версию и описание подставляет генератор [tools/sync.py](tools/sync.py) из `skill.json`. Тело ссылается на AGENTS.md, tutor-modes.md и `handoff.py` и передаёт текст ученика команде проверки через heredoc, который shell не раскрывает.
- Добавлены тесты [test_source.py](tests/test_source.py): заголовок, ссылки на правила проекта, единственный `$ARGUMENTS` внутри heredoc, строка использования из контракта и из кода, флаги из шаблона, текст ученика с `$(…)` и обратными кавычками не выполняется shell.
