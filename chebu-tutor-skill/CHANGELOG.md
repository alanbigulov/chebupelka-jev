# История изменений chebu-tutor

Здесь фиксируются существенные изменения навыка `chebu-tutor`. Номер версии хранит [skill.json](skill.json). Правила номеров, тегов и выпуска описаны в [versioning.md](chebu-tutor-docs/versioning.md). Изменения `chebu` ведёт [CHANGELOG.md](../CHANGELOG.md) проекта.

## [Unreleased]

### Адаптеры в рантаймах

- Генератор записал адаптеры в настоящее дерево: `.claude/skills/chebu-tutor/SKILL.md`, `.claude/skills/chebu-tutor/agents/openai.yaml` и ссылку `.agents/skills/chebu-tutor` на `../../.claude/skills/chebu-tutor`. Новый clone получает команду `/chebu-tutor --<режим>` без установки, в Codex `$chebu-tutor --<режим>`.
- [tutor-modes.md](../coding-agent-developement/tutor-modes.md) объясняет ученику вызов навыка: таблица флагов с примерами и ссылка на [контракт](chebu-tutor-docs/contract.md). На навык ссылаются AGENTS.md, корневой README и project-structure.md.

### Генератор адаптеров

- Добавлен [tools/sync.py](tools/sync.py). Без ключа он записывает адаптеры по блокам `skill` из `runtime-config/runtimes/`: папку `.claude/skills/chebu-tutor/` и символическую ссылку `.agents/skills/chebu-tutor` на неё. С ключом `--check` он ничего не пишет, называет каждый расходящийся путь и выходит с кодом 1. Расхождением считается и файл в папке адаптера, которого нет в `source/`. Повторный запуск ничего не меняет. Файлы и папки генератор не удаляет и через ссылки не пишет, а ссылку на месте файла адаптера или ссылку Codex с другим текстом заменяет. Папку или файл на месте ссылки, ссылку или файл на месте папки адаптера и лишний файл он называет и выходит с кодом 1 до первой записи.
- Папка адаптера повторяет [source/](source/). `SKILL.md` получает версию и описание из `skill.json` и пометку о генерации первой строкой тела. Добавлен [source/agents/openai.yaml](source/agents/openai.yaml) с `policy.allow_implicit_invocation: false`: Codex не вызывает навык сам, явный `$chebu-tutor` работает.
- Генератор проверяет, что источник называет каждый флаг из перечисления «Режим тьютора» [шаблона](../.handoff/TEMPLATE.md) и строку использования, которую печатает `handoff.py`.
- В каждый файл `runtime-config/runtimes/<id>.json` добавлен блок `skill`: папка навыка `dir`, у Codex ещё `link_to`.
- Добавлен 21 тест [test_sync.py](tests/test_sync.py). Каждый работает на временной копии дерева и ловит свой дефект: ручную правку адаптера, дрейф версии, рантайм без блока, повторную запись, запись вне путей блоков и через ссылку, копию вместо ссылки, лишний файл в адаптере, опечатку в блоке, новый режим.

### Проверка флага и канонический текст

- `python3 .handoff/handoff.py start --runtime <id> --mode` читает слова вызова навыка из stdin и проверяет флаг режима до брифинга. Два флага, флаг вне списка или неподставленный `$ARGUMENTS` дают отказ с кодом 2 и строкой использования. Без флага команда печатает строку использования и обычный брифинг. С флагом строка `Режим тьютора:` сравнивает флаг с режимом снимка. Флаги строятся из перечисления «Режим тьютора» в [шаблоне](../.handoff/TEMPLATE.md). Без ключа `--mode` команда работает как прежде.
- Добавлены 11 тестов `ModeTest` в [test_handoff.py](../.handoff/test_handoff.py).
- Добавлен канонический текст [source/SKILL.md](source/SKILL.md). Заголовок запрещает вызов моделью полями `disable-model-invocation` и `triggers`. Версию и описание подставляет генератор [tools/sync.py](tools/sync.py) из `skill.json`. Тело ссылается на AGENTS.md, tutor-modes.md и `handoff.py` и передаёт текст ученика команде проверки через heredoc, который shell не раскрывает.
- Добавлены тесты [test_source.py](tests/test_source.py): заголовок, ссылки на правила проекта, единственный `$ARGUMENTS` внутри heredoc, строка использования из контракта и из кода, флаги из шаблона, текст ученика с `$(…)` и обратными кавычками не выполняется shell.
