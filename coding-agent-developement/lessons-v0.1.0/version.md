## Проверка тега и содержимого

Из корня любой рабочей копии этого репозитория:

```bash
git rev-parse 'v0.1.0^{}'
git show v0.1.0:pyproject.toml
git show v0.1.0:.python-version
git show v0.1.0:chebupelkajev.py
```

Проверенное разрешение тега:

```text
f6108317f85553eb6acdec7dc94fe13ba115b367
```

`^{}` раскрывает аннотированный тег до коммита. Для лёгкого тега результатом тоже будет его коммит. `git show` читает сохранённое содержимое и не меняет текущие файлы.

## Отдельная рабочая копия для запуска

Если соседняя рабочая копия ещё не создана, выполни из корня текущего репозитория:

```bash
git worktree add --detach ../chebupelkajev-v0.1.0 v0.1.0
cd ../chebupelkajev-v0.1.0
git rev-parse HEAD
uv sync --locked
uv run --locked python --version
uv run --locked python -c 'import requests; print(requests.__version__)'
```

Создавать worktree нужно один раз. Если копия уже существует, перейди в неё и проверь `HEAD`. Он должен совпадать с полным SHA выше. `uv` создаёт `.venv` в этой старой рабочей копии, отдельно от окружения текущего агента.

При подготовке v0.1.1 эта копия создана на учебной машине. `uv sync --locked --offline` подготовил отдельное окружение с CPython 3.14.7 и Requests 2.34.2. Проверены реальный `pwd` и два хода агента с подставными HTTP-ответами; файлы снимка не изменились. Облачный API при восстановлении не вызывался.

Команды запуска и проверки из уроков выполняй в корне этой копии. Команды с прежним именем `chebupelka.py` остаются записью первой сессии; в выпущенном снимке файл называется `chebupelkajev.py`. Историческое объединение Git заново выполнять для запуска снимка не требуется.

Режим `--detach` открывает коммит без переключения ветки текущего проекта. Для учебных изменений можно создать ветку внутри старой копии:

```bash
git switch -c lab/v0.1.0
```

## Что подтверждала первая сессия

В первой сессии получен HTTP 200 от DeepSeek и пройден цикл с одним `bash`-вызовом `pwd`, затем финальным ответом. Это исторический результат. Подготовка v0.1.1 не повторяет облачные запросы и не доказывает работу всех ошибок или нескольких инструментов.

Git фиксирует Python-исходник, настройки и lock-файл. Имя `deepseek-flash` выбирает модель у провайдера; Git не фиксирует её реализацию, доступность сети или будущий ответ. `.python-version` выбирает ветку `3.14`, но сама по себе не закрепляет патч `3.14.7`.
