# Трекинг разработки и учебных материалов chebupelkajev

GitHub Issues и публичный GitHub Project являются основным трекером задач. Этот документ задаёт правила работы; актуальные состояния, обсуждения и доказательства находятся в GitHub. Учебный roadmap объясняет смысл задач и ссылается на тикеты.

Проект: [chebupelkajev — Разработка и обучение](https://github.com/users/alanbigulov/projects/4). Репозиторий: https://github.com/alanbigulov/chebupelka-jev.

## Представления одного проекта

| Представление | Что показывает |
|---|---|
| [Общая доска](https://github.com/users/alanbigulov/projects/4/views/1) | Все задачи кода, обучения и выпуска |
| [Код агента](https://github.com/users/alanbigulov/projects/4/views/2) | Issues с меткой area:agent |
| [Учебные материалы](https://github.com/users/alanbigulov/projects/4/views/3) | Issues с меткой area:learning |

Это три Board-представления одной очереди, а не копии тикетов. Поле колонок каждого представления: `Status`. Перемещение карточки меняет Status этого же project item. Горизонтальная дополнительная группировка не настроена.

```text
GitHub Issue / ticket
      |
      v
Один item в Project
      |
      +--> Общая доска
      +--> Код агента: label area:agent
      `--> Учебные материалы: label area:learning
```

## Где находится источник данных

| Данные | Источник |
|---|---|
| Задача, критерии, обсуждение, проверенные результаты | GitHub Issue |
| Этап выполнения | Поле Status в Project |
| Целевая версия | Milestone issue, отображаемый в Project |
| Приоритет и рекомендуемая последовательность | Поля Приоритет и Порядок в Project |
| Область и тип задачи | Labels issue |
| Учебный смысл, место изменения и исторические решения | [development-roadmap.md](development-roadmap.md) |
| История изменения структуры | [project-structure.md](project-structure.md) |
| Передача текущей локальной сессии | Игнорируемая папка `.handoff/` |

Issue является тикетом. Не создавай отдельный draft item для уже существующего issue. Для продолжения задачи используй её номер и стабильный ID EDU; перед созданием новой ищи совпадения в открытых и закрытых issues.

## Колонки и переходы

| Status | Когда использовать |
|---|---|
| Бэклог | Идея записана, исполнение ещё не согласовано или не начато |
| К выполнению | Согласованы конкретный объём и критерии следующего шага |
| В работе | Агент или человек действительно выполняет задачу |
| Проверка | Изменение готово, результат и критерии ещё проверяются |
| Заблокировано | Записаны конкретное препятствие, ответственное действие и условие снятия |
| Готово | Согласованные критерии проверены, доказательства записаны и issue закрыт |

```text
Бэклог -> К выполнению -> В работе -> Проверка -> Готово
                                |         |
                                +---------+--> Заблокировано
                                                  |
                                  после устранения +--> предыдущий этап
```

Создание тикета не разрешает автоматически реализовать его. Перед началом согласуй с владельцем минимальный план. Не отмечай В работе задачу, к которой никто не приступил. Отсутствие текста модели, завершение программы или успешный импорт сами по себе не доказывают достижение критериев задачи.

Частичное выполнение отражается чек-листом и меткой `status:partial`; issue остаётся открытым. EDU-06 уже имеет две проверенные части, но остальные сценарии пока не реализованы. После завершения всей задачи удали метку частичности.

Закрытие issue и Status проекта являются разными состояниями. После закрытия явно проверь колонку Готово. При повторном открытии верни карточку на подходящий этап. Не полагайся на автоматические workflow без проверки их результата.

| type:feature | Новая возможность |
| type:testing | Проверки поведения |
| type:documentation | Учебные и справочные документы |

| status:partial | Проверена только часть критериев |

Приоритет имеет варианты Высокий, Средний, Низкий. Порядок является числом и задаёт рекомендуемую последовательность; он не является дедлайном и не означает автоматическое начало работы. В интерфейсе при необходимости выбери сортировку по Порядок.

На карточках всех трёх досок отображаются название, исполнитель, labels, milestone, Приоритет и Порядок. Status задаёт колонку. Конфигурация и значения полей проверены через GitHub API; визуальный просмотр браузером в этой сессии не выполнялся.

Milestone v0.1.2 закрывается только при отсутствии открытых задач его согласованного состава. EDU-06 сохраняет status:partial; перенос в v0.1.3 не меняет её критерии на выполненные.

Состояние GitHub меняется независимо от Git-тега. Для статуса закрытия проверяй живой issue, Project и milestone, а не только текст снимка.

## Шаблон нового тикета

```markdown
## Контекст и учебная тема
Что наблюдается сейчас, где находится код, какая версия является исходной базой.

## Цель и границы
Одна проверяемая задача. Что требуется согласовать до изменения.

## Критерии готовности
- [ ] Наблюдаемый результат.
- [ ] Необходимые проверки.
- [ ] Учебное объяснение и ссылки, если задача меняет изучаемый код.

## Связанные задачи
ID/URL зависимостей, учебного тикета и приёмки выпуска.

## Источники
Ссылки на исходники конкретной версии, уроки и решения.

## Запись завершения
Коммит/PR, команды и результаты проверок, непроверенные сценарии, принятое решение.
```

Добавь одну область, тип и milestone; затем добавь существующий issue в Project и заполни Status, Приоритет и Порядок. Секреты, локальные логи с личными данными и содержимое `.handoff/` не публикуются.

## Работа в каждой сессии

1. Прочитай локальный handoff, если он существует, и перепроверь Git и актуальный issue/Project.
2. Выбери конкретный тикет и согласуй объём с владельцем; при необходимости уточни критерии в issue.
3. Перед реальной работой обнови Status и записывай существенные решения и результаты.
4. Выполни проверки, запиши доказательства и ограничения. Закрывай задачу только при выполнении согласованных критериев.
5. Сверь состояние issue и Project. При изменении учебного смысла обнови roadmap и уроки.
6. Заверши сессию локальным handoff по единому шаблону. Передача содержит ссылки и наблюдения, а не копию всей документации.

Локальные файлы `.handoff/README.md`, `.handoff/TEMPLATE.md`, `.handoff/SESSION.md` и архив доступны разным агентам в этой рабочей директории. Они исключены из Git и не появляются после нового клонирования; для другой машины требуется отдельная приватная передача папки. Публичный трекер позволяет восстановить задачи, но не заменяет незаписанный локальный контекст.
