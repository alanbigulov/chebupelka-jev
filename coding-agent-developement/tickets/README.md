## Работать по тикету

1. Выбери тикет вместе с учеником и прочитай его файл целиком.
2. Проверь, что тикет открыт в рабочей копии. Критерий с отметкой `[x]` уже выполнен в исходной базе. Если код рабочей копии уже содержит решение, начни со снимка, в котором тикет открыт.
3. Воспроизведи нынешнее поведение и согласуй с учеником минимальный план.
4. Веди работу в выбранном [режиме тьютора](../tutor-modes.md).
5. Отмечай статус и критерии в трекере ученика.

## Общие границы

Эти правила относятся к каждому тикету и в файлах тикетов не повторяются.

- Сначала воспроизведи нынешнее поведение и согласуй минимальный план.
- Реализуй только выбранный тикет. Остальные задачи ждут отдельного решения ученика.
- Частичное выполнение не закрывает тикет: оставшиеся критерии перечисляются явно.
- Целевая версия в трекере владельца предварительная и срока не имеет.

## Запись завершения

Тикет закрывается, когда каждый критерий отмечен и доказательства записаны в трекере: коммит или PR, выполненные команды и их результаты, непроверенные сценарии и ссылка на учебное объяснение.

## С какого снимка начинать

Тикет решается на коде, в котором он ещё открыт. Поле «Исходная база» называет версию, в которой поведение описано.

Сейчас `agent/chebu.py` в `main` побайтово совпадает с исходником версии v0.1.1, поэтому все двенадцать тикетов открыты и ученик начинает с `main` своего клона. Работу по тикету удобно вести на отдельной ветке.

Когда тикет будет решён в `main`, новый ученик начнёт с последнего тега, в котором тикет открыт. Такой тег должен содержать `AGENTS.md`, эту папку и навык `chebu-tutor`, которым сессия начинается по умолчанию. Первый такой тег: `chebu-tutor-v0.1.0`, в нём открыты все двенадцать тикетов, а код `agent/` совпадает с v0.1.4. В теге v0.1.4 `AGENTS.md` и эта папка уже есть, а навыка нет: сессию в ветке от него начинают промптом. В тегах до v0.1.3 включительно `AGENTS.md` и этой папки нет. Список снимков и команды восстановления описывает [VERSIONING.md](../../VERSIONING.md).

## Откуда взяты тексты

Файлы созданы из issues #1–#12 [трекера владельца](https://github.com/alanbigulov/chebupelka-jev/issues) скриптом `issues_sync.py`. Скрипт сохраняет критерии и источники, переносит общие разделы в этот README и заменяет ссылки на `main` относительными. Источником текста тикета с этого момента служит файл.

Два критерия скрипт переформулирует, чтобы ученик мог выполнить их без доступа к трекеру владельца. Запись результатов «в issue» становится записью «в трекере: в issue или в снимке `.handoff/`». Привязка к целевой версии владельца становится привязкой к версии, в которую изменение входит. В этих двух строках файл и issue различаются намеренно, и проверка расхождением это не считает.

Владелец репозитория продолжает вести issues как зеркало. Расхождение между файлом и issue показывает проверка:

```bash
python3 coding-agent-developement/tickets/issues_sync.py
```

Проверке нужны установленный `gh` и доступ к сети. Ученику без собственного трекера на GitHub она не нужна.
