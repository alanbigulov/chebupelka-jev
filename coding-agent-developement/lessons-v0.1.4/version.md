# Паспорт учебного снимка v0.1.4

В v0.1.4 учебную сессию ведёт кодинговый агент в любом из шести рантаймов. Выпуск добавляет правила для агента, передачу сессии между рантаймами, режимы тьютора и тикеты в репозитории. Логика агента, зависимости и два существующих локальных теста сохранены. Отдельного урока у выпуска нет. Порядок работы объясняют раздел «Как проходит учебная сессия» в [README проекта](../../README.md) и [режимы тьютора](../tutor-modes.md).

## Проверка снимка

После публикации тега выполни из корня репозитория:

```bash
git rev-parse 'v0.1.4^{}'
git show v0.1.4:agent/pyproject.toml
git rev-parse v0.1.3:agent/chebu.py v0.1.4:agent/chebu.py
git ls-tree --name-only v0.1.4 AGENTS.md CLAUDE.md .handoff/ runtime-config/ coding-agent-developement/tickets/
```

Третья команда печатает два идентификатора содержимого. Они должны совпасть: выпуск не меняет программу. При подготовке выпуска оба идентификатора равны `2fb8801cc5aec94849f5b5157ee47c4c5a558a8a`, тот же идентификатор имеет исходник v0.1.0. Четвёртая команда перечисляет файлы, которые появились в этом выпуске. Для тега v0.1.3 она печатает пустой список.

Локальные проверки скриптов запускаются из корня и не требуют сети:

```bash
python3 -m unittest discover -s .handoff -p 'test_*.py'
python3 -m unittest discover -s coding-agent-developement/tickets -p 'test_*.py'
```

Для подготовки окружения и проверок агента перейди в `agent/`:

```bash
cd agent
uv sync --locked
uv run --locked python --version
uv run --locked python -m unittest discover -s tests -v
```

`3.14` в настройке выбирает ветку интерпретатора. Фактический патч показывает `python --version`; для выбора проверенного патча можно использовать `uv sync --locked --python 3.14.7`. При восстановлении выпуска не обновляй lock-файл.

Начало первой сессии проверяется в свежем клоне из его корня:

```bash
python3 .handoff/handoff.py start --runtime unknown
```

Команда печатает «Снимок: нет. Это первая сессия в этом клоне» и называет раздел «Первая сессия» протокола.

| Проверка | Граница результата |
|---|---|
| Сохранность программы | Содержимое `agent/chebu.py` совпадает с v0.1.3 и с исходником v0.1.0 |
| Локальные тесты агента | Два существующих теста с синтетическими HTTP-ответами проходят. Новых сценариев нет |
| Скрипт передачи | 63 теста: проверка снимка, архив, сохранение из git worktree, распознавание рантайма |
| Скрипт тикетов | 33 теста. Сверка `issues_sync.py` показывает, что двенадцать файлов совпадают с issues владельца |
| Генерация тикетов | В свежем клоне `issues_sync.py --write` записывает двенадцать файлов и не меняет рабочее дерево |
| Первая сессия | `start` в свежем клоне сообщает о первой сессии. Полная первая сессия под управлением рантайма не проводилась |
| Передача между рантаймами | 13 октября 2026 года одна сессия прошла через шесть рантаймов, таблица ниже |
| Распознавание рантайма без ключа `--runtime` | Наблюдалось в сессии Claude Code. В сессиях Codex, OpenCode, Grok и Cursor не запускалось. Своя переменная Devin не найдена |
| Правка кода тикета | В проверочной сессии код тикета не правил никто. Правка агента в режиме `execute` и проверка работы ученика в режиме `guide` не проверялись |
| Границы записи в режимах | Заданы инструкцией. Скрипт их не контролирует |
| Сессия в worktree снимка | Не проводилась. Проверочная сессия шла в основном клоне |
| Lock-файл | `uv lock --check` проходит с uv 0.5.15 и 0.12.14; изменилась только версия локального пакета |
| Ссылки документов | Относительные ссылки ведут на существующие файлы |

Проверочная сессия шла в основном клоне. Рантаймы запускал владелец, и каждый получал снимок предыдущего.

| Шаг | Рантайм | Версия CLI | Режим из снимка | Что сделано по фразе ученика |
|---|---|---|---|---|
| 1 | Claude Code | 2.1.296 | `execute` | Смена на `walkthrough`, разбор `run_bash()` |
| 2 | Codex | 0.162.1 | `walkthrough` | Разбор `call_tool()`, смена на `quiz`, один вопрос |
| 3 | OpenCode | 2.0.27 | `quiz` | Проверка ответа, смена на `sandbox`, пример в `.sandbox/` |
| 4 | Grok | 1.0.52 | `sandbox` | Смена на `guide`, тикет EDU-06, подсказка уровня 1 |
| 5 | Cursor | 2026.10.01-e373342 | `guide` | Подсказка уровня 2 |
| 6 | Devin | 3000.11.3 | `guide` | Смена на `execute`, отметка прогресса EDU-06 в снимке |

Каждый рантайм выполнил `handoff.py start` первой командой. Режим пять раз перешёл из рантайма в рантайм без повторного вопроса. Файлы проекта не изменил никто, в том числе код тикета. Полный итог записан в [issue #18](https://github.com/alanbigulov/chebupelka-jev/issues/18#issuecomment-6152440082).

Тесты агента подменяют `requests.post` и не обращаются к DeepSeek. Во время этого выпуска облачные запросы не выполнялись. Облачные сессии рантаймов и агент внутри приложения Cursor не проверялись. Облачная сессия локальную папку `.handoff/` не видит и в передаче не участвует.

EDU-06 остаётся частично выполненной. EDU-01, EDU-02, EDU-03 и оставшаяся часть EDU-06 перенесены в предварительную v0.1.5.

## Что сохраняет тег

Тег фиксирует исходники, метаданные, правила для агента, протокол и скрипт передачи, конфигурации рантаймов, тексты тикетов и документы. Состояние сессии ученика, папка `.sandbox/` и локальные окружения в Git-снимок не входят. GitHub Issues, Project, их статусы и milestones остаются изменяемыми внешними объектами; актуальное состояние задачи следует читать в GitHub.

Тег v0.1.4 первым содержит `AGENTS.md` и тикеты, и все двенадцать тикетов в нём открыты. Когда тикет будет решён в `main`, ученик начнёт его с этого тега на своей ветке. Команда записана в [VERSIONING.md](../../VERSIONING.md), раздел «Создать отдельный снимок».

Выпуск принимается по задачам [#18](https://github.com/alanbigulov/chebupelka-jev/issues/18), [#19](https://github.com/alanbigulov/chebupelka-jev/issues/19) и [#20](https://github.com/alanbigulov/chebupelka-jev/issues/20). Отдельного выпускного тикета нет. Порядок завершения описан в [VERSIONING.md](../../VERSIONING.md): проверка материалов, закрытие трёх issues с проверкой Status, слияние pull request, публикация тега, сверка SHA, закрытие milestone. Наличие паспорта само по себе не подтверждает выполнение этих шагов.

Имя облачной модели `deepseek-flash` не фиксирует её внутреннюю версию или ответы.
