# История изменений chebu

Все существенные изменения самостоятельного учебного проекта фиксируются здесь. Правила номеров и выпуска описаны в [VERSIONING.md](VERSIONING.md).

## [Unreleased]

Исправления кода следующей версии пока не реализованы. План и критерии готовности ведутся в [development-roadmap.md](coding-agent-developement/development-roadmap.md).

### Работа с кодинговыми агентами

Правки закрывают находки 1–7 совместной сессии шести рантаймов. Итог сессии записан в [#18](https://github.com/alanbigulov/chebupelka-jev/issues/18#issuecomment-6152440082). Находка 9, распознавание рантайма по значению `AI_AGENT`, не реализована: значение не наблюдалось в сессиях OpenCode и Devin.

- Агент называет режим из снимка вместе с выводом команды `start`. Прежнее правило требовало первого сообщения, а до `start` режим неизвестен.
- [AGENTS.md](AGENTS.md) напоминает перечитать issue и карточку Project при начале сессии, если ученик ведёт GitHub-адаптер. [Протокол](.handoff/README.md) в том же месте напоминает о ключе `-R`.
- Режим `quiz` запрещает агенту писать верный ответ и запускать проверку до ответа ученика, а также записывать этот ответ в снимок.
- [Шаблон снимка](.handoff/TEMPLATE.md) получил строки для файлов вне репозитория и для дословных договорённостей с учеником. Протокол описывает, что в них писать, и оговаривает, что фразы ученика из снимка разрешением не становятся.
- Протокол описывает, что `start` без ключа `--runtime` завершается с кодом 2, когда признак рантайма не найден или найдено несколько, и что команды продолжения из `save` рассчитаны на корень основного клона.
- [tickets/README.md](coding-agent-developement/tickets/README.md) объясняет два критерия, которые `issues_sync.py` переформулирует.
- Каталог `.claude/worktrees/` исключён из Git.
- Чек-лист выпуска в [VERSIONING.md](VERSIONING.md) требует обновить milestones до коммита выпуска.

### Учебное сопровождение

- [tutor-modes.md](coding-agent-developement/tutor-modes.md) получил раздел «Вопросы и ответы о режимах»: двенадцать вопросов ученика о выборе и смене режима, границах записи и переносе режима между рантаймами.
- [tutor-modes.md](coding-agent-developement/tutor-modes.md) получил раздел «Как начать сессию: промпты для ученика»: короткий и полный промпт, команды запуска шести рантаймов, промпты для десяти ситуаций и пяти режимов, строки ограничений и фразы для работы внутри сессии.
- В режиме `guide` формулировка шага больше не называет похожий тест, фикстуру или функцию-образец: это подсказка уровня 1, и агент даёт её только по просьбе ученика. На приёмке `chebu-tutor` 2026-10-18 агенты Codex и Devin по одному разу назвали такой образец без просьбы.

### Навык chebu-tutor

- Добавлен каталог [chebu-tutor-skill/](chebu-tutor-skill/README.md) с пакетом документации [chebu-tutor-docs](chebu-tutor-skill/chebu-tutor-docs/README.md). Пакет описывает навык, который ведёт учебную сессию в режиме из флага `--execute`, `--guide`, `--walkthrough`, `--sandbox` или `--quiz` одинаково в шести рантаймах: контракт, архитектуру, свою SemVer с тегами `chebu-tutor-vX.Y.Z`, факты о каталогах навыков рантаймов и семь этапов разработки для сессий Claude Code.
- Навык `chebu-tutor` установлен в клоне: адаптеры лежат в `.claude/skills/chebu-tutor/` и `.agents/skills/chebu-tutor`. Ученик начинает сессию командой `/chebu-tutor --<режим>`, в Codex `$chebu-tutor --<режим>`, как описывает [tutor-modes.md](coding-agent-developement/tutor-modes.md#начать-сессию-командой-chebu-tutor). Изменения навыка ведёт [CHANGELOG навыка](chebu-tutor-skill/CHANGELOG.md).
- Строка [AGENTS.md](AGENTS.md) о `/chebu-tutor` ведёт на файл навыка, а не на контракт: агент выполняет навык вместо шага 1 «Начни сессию», даже когда рантайм не приложил текст навыка к сообщению. В интерфейсе OpenCode 2.0.32 так и было 2026-10-19: агент начал сессию без проверки флага.
- Выпущен навык `chebu-tutor` 0.1.0, тег `chebu-tutor-v0.1.0`. Приёмку прошли все 54 ячейки матрицы в шести рантаймах. Состав выпуска и итоги по рантаймам перечисляет [раздел 0.1.0](chebu-tutor-skill/CHANGELOG.md#010-2026-10-19) CHANGELOG навыка. Версия `chebu` не меняется.
- Сессию по умолчанию начинает команда `/chebu-tutor --<режим>`. Раздел [tutor-modes.md](coding-agent-developement/tutor-modes.md) «Как начать сессию: промпты для ученика» стал «Как начать сессию»: команды навыка по ситуациям и режимам, разрешения после флага, промпты в подразделе «Без навыка: промпт». Быстрый старт корневого README тоже начинается с команды навыка. [README навыка](chebu-tutor-skill/README.md) стал инструкцией для ученика.

## [0.1.4], 2026-10-13

Выпуск для работы с кодинговыми агентами: правила для ведущего агента, передача сессии между шестью рантаймами, режимы тьютора и тикеты в репозитории. Логика агента и два существующих теста сохранены.

### Работа с кодинговыми агентами

- Добавлен корневой [AGENTS.md](AGENTS.md) с правилами для ведущего агента. Его читают Codex, Claude Code, OpenCode, Grok, Cursor и Devin; `CLAUDE.md` указывает на него. Раньше правила лежали в настройках Codex и в стартовом prompt.
- Протокол и шаблон передачи сессии теперь хранятся в Git: [.handoff/README.md](.handoff/README.md) и [.handoff/TEMPLATE.md](.handoff/TEMPLATE.md). Снимок `SESSION.md` и `archive/` по-прежнему исключены из Git.
- Схема снимка получила номер 2: добавлены поля рантайма и рабочей копии, раздел о стартовом prompt сокращён до задачи сессии.
- Добавлен `runtime-config/` с конфигурациями шести рантаймов. Каждый файл отделяет подтверждённые факты от неподтверждённых.
- Добавлен `.handoff/handoff.py`. Команда `start` определяет рантайм и показывает положение снимка, `check` проверяет снимок, `save` архивирует прежний снимок и атомарно записывает новый в основной клон, в том числе из git worktree.
- Совместная сессия 13 октября 2026 года прошла через шесть рантаймов. Каждый рантайм сам выполнил `handoff.py start` и продолжил сессию по снимку предыдущего. Наблюдения записаны в `runtime-config/runtimes/`.
- Облачные сессии локальное состояние не видят и в передачу не входят. Задача: [#18](https://github.com/alanbigulov/chebupelka-jev/issues/18).

### Учебное сопровождение

- Добавлены пять режимов тьютора: `execute`, `guide`, `walkthrough`, `sandbox`, `quiz`. Правила каждого описывает [tutor-modes.md](coding-agent-developement/tutor-modes.md).
- Режим выбирает ученик. Снимок сессии хранит режим в метаданных и подробности в разделе «Учебное состояние», поэтому следующий рантайм продолжает режим без повторного вопроса.
- `handoff.py check` отклоняет снимок с режимом вне списка, `start` печатает режим из снимка.
- [tutor-modes.md](coding-agent-developement/tutor-modes.md) объясняет ученику, как выбрать режим и как режим переходит в следующую сессию. Документ содержит пример сессии в пяти режимах и называет то, что режим не контролирует.
- Для режима `sandbox` добавлена локальная папка `.sandbox/`, исключённая из Git. Задача: [#19](https://github.com/alanbigulov/chebupelka-jev/issues/19).

### Старт для ученика после клонирования

- Тексты тикетов EDU-01–EDU-12 перенесены из issues в [coding-agent-developement/tickets/](coding-agent-developement/tickets/README.md). Критерии, которые требовали записи в трекере владельца, переформулированы так, чтобы ученик мог выполнить их без доступа к нему.
- Трекером ученика служит снимок сессии: раздел «Тикет и трекер» хранит статус, отмеченные критерии и доказательства. GitHub Issues и Project описаны в [правилах учёта](coding-agent-developement/project-tracking.md) как необязательный адаптер.
- `tickets/issues_sync.py` показывает расхождение между файлом тикета и issue владельца.
- README получил раздел о начале обучения с любым из шести рантаймов. Оговорка про отдельный экземпляр `uv` убрана: проект проверен с uv 0.5.15 и 0.12.14. Задача: [#20](https://github.com/alanbigulov/chebupelka-jev/issues/20).
- README получил раздел «Как проходит учебная сессия»: первая сессия, режим и тикет, место хранения прогресса, продолжение в другом рантайме, проверенные и непроверенные сценарии.
- Тег v0.1.4 первым содержит `AGENTS.md` и тикеты. Когда тикет будет решён в `main`, ученик начнёт его с этого тега на своей ветке; команда записана в [VERSIONING.md](VERSIONING.md).

## [0.1.1], 2026-10-07

Структурный учебный выпуск. Логика агента побайтово сохранена относительно v0.1.0. По решению владельца выпуск получает номер v0.1.1, хотя путь и каталог запуска изменились.

### Разделение модулей

- Python-файл, `pyproject.toml`, `uv.lock` и `.python-version` перенесены из корня в `agent/`.
- Версия проекта и локального пакета в lock-файле обновлена до `0.1.1`; версии зависимостей сохранены.
- Создан README исполняемого модуля; корневой README стал обзором проекта и курса.
- Создано отдельное локальное окружение `agent/.venv`; прежнее корневое окружение оставлено для отката и не входит в Git.

### Снимки и обучение

- В учебный модуль добавлен `project-structure.md` с причинами решений, правилами размещения и журналом изменений.
- Пакеты уроков v0.1.0 и v0.1.1 получили `version.md` с привязкой к коду и командами восстановления.

- Добавлен урок v0.1.1 о разделении проекта, тегах, worktree и границах воспроизводимости.
- На учебной машине создан соседний worktree `chebupelkajev-v0.1.0` с отдельным окружением. Эта папка не является частью коммита и на другой машине создаётся вручную.

### Проверки

- Добавлены два теста на стандартном `unittest`: обычный текстовый ответ и один `pwd` с полным результатом и ID инструмента во втором запросе.
- Синтетические JSON fixtures созданы вручную; `requests.post` подменяется, облачные запросы не выполняются.
- Подготовлены оба окружения через `uv sync --locked --offline`; проверены одинаковые исходники и сохранность старого тега.

## [0.1.0], 2026-10-07

Первый выпуск самостоятельного учебного проекта на основе [chebupelka](https://github.com/alexey-goloburdin/chebupelka) Алексея Голобурдина.

### Подготовка и происхождение

- Исходная история добавлена через remote `upstream` и объединена с собственным репозиторием с помощью `--allow-unrelated-histories`.
- Конфликт двух независимо добавленных README разрешён сохранением документа автора на этапе установки.
- Создана `.venv` с Python 3.14.7 через Homebrew `uv` 0.12.14; зависимости установлены и проверены.
- Исправлено старое имя `agent-loop` в lock-файле, затем имя текущего проекта обновлено до `chebupelkajev`.

### Подключение модели

- Настроены `https://api.deepseek.com` и API-идентификатор модели `deepseek-flash`.
- Ключ читается из `DEEPSEEK_API_KEY`, вместо записи в исходники.
- В запрос добавлено `thinking: {"type": "disabled"}`, чтобы текущий цикл не требовал обработки `reasoning_content`.

### Самостоятельный проект и обучение

- `chebupelka.py` переименован в `chebupelkajev.py`; логика существующего агента сохранена.
- Имя проекта согласовано в `pyproject.toml` и `uv.lock`; версия зафиксирована как `0.1.0`.
- README заменён актуальными инструкциями самостоятельного проекта с сохранением ссылки на автора.
- Созданы три подробных урока в `coding-agent-developement/lessons-v0.1.0/`, навигация и трекер будущих улучшений.
- Добавлены правила версии и этот журнал. Оба файла имеют право исполнения `+x`, но содержат Markdown, а не программы.
- Выпуск фиксируется аннотированным Git-тегом `v0.1.0`.

### Проверенные сценарии и границы проверки

В обучающей сессии до переименования API вернул `HTTP 200` и ответ `Да`. Агент выполнил `pwd` одним вызовом инструмента и завершился после двух обращений к модели. Версии Python и `requests` проверены запуском в окружении проекта.

При подготовке выпуска Python-код побайтово сравнен с предыдущим коммитом. Проверены метаданные и lock-файл через `uv lock --check --offline`, реальная команда `pwd` через `call_tool()` и двухходовый цикл с подставными HTTP-ответами без сетевого запроса. Повторная проверка облачного сервиса в выпуск не входит. Известные ограничения обработки нескольких инструментов, ошибок HTTP и выполнения shell-команд остаются открытыми задачами roadmap.
