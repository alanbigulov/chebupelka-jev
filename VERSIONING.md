# Версионирование chebupelkajev

## Текущая версия

Текущий учебный выпуск: **v0.1.1**. Версия проекта в [agent/pyproject.toml](agent/pyproject.toml) и запись локального проекта в [agent/uv.lock](agent/uv.lock) имеют значение `0.1.1`. Git-тег использует префикс `v`. Базовый выпуск `v0.1.0` сохранён без изменения тега.

История выпусков находится в [CHANGELOG.md](CHANGELOG.md), задачи будущих версий в [roadmap](coding-agent-developement/development-roadmap.md). Это описание процесса, а не автоматический механизм обновления версии.

## Источник версии и смысл номера

Источником номера служит `project.version` в `agent/pyproject.toml`. Запись в lock-файле, документация и тег должны соответствовать этому значению. Номер старых уроков и исторических разделов CHANGELOG не заменяется номером текущего выпуска.

```text
agent/pyproject.toml: 0.1.1
        |
        +--> agent/uv.lock: 0.1.1
        +--> CHANGELOG.md: [0.1.1]
        +--> Git-тег: v0.1.1
        +--> lessons-v0.1.1/: уроки этого выпуска
```

Используем схему `MAJOR.MINOR.PATCH`:

| Часть | Когда повышать | Пример |
|---|---|---|
| PATCH | Исправления без смены публичного способа работы | `0.1.0` → `0.1.1` |
| MINOR | Новые учебные возможности или заметное изменение контракта до 1.0 | `0.1.0` → `0.2.0` |
| MAJOR | Несовместимые изменения стабильного публичного контракта | `1.0.0` → `2.0.0` |

До `1.0.0` проект экспериментальный. Возможные несовместимости описываются явно в истории изменений и новых уроках. Предлагаемые в roadmap номера не являются обещанием выпустить функции вместе.

Выпуск `v0.1.1` получил PATCH-номер по прямому решению владельца. Логика агента сохранена, но путь исходника и рабочая директория обычного запуска изменились. Этот случай явно зарегистрирован в CHANGELOG и [журнале структуры](coding-agent-developement/project-structure.md).

## Чек-лист следующего выпуска

1. Выбрать задачи roadmap и согласовать ожидаемое поведение.
2. Проверить чистоту рабочей директории, чтобы не включить чужие изменения.
3. Обновить `project.version` в `agent/pyproject.toml`, затем из `agent/` согласовать lock-файл через `uv lock`.
4. Проверить код, команды запуска, ссылки и отсутствие ключей в подготовленных изменениях.
5. Записать фактические изменения и результаты проверок в `CHANGELOG.md`.
6. Добавить уроки новой версии, паспорт `version.md` и обновить навигацию. Старые уроки не переписывать под новую реализацию; ссылки на исторический код закрепить за их снимком.
7. Создать коммит выпуска, аннотированный тег на нём и отправить ветку и тег.
8. Сверить локальный и удалённый коммит, включая коммит, на который указывает тег.

## Команды выпуска

Команды Git запускаются вручную из корня. Пример для структурного выпуска; после появления тега не выполняй их повторно для той же версии.

```bash
git status --short --branch
git diff --check
git diff --cached --check
git diff --cached --stat
git commit -m "Release chebupelkajev v0.1.1 with separated modules and snapshots"
git tag -a v0.1.1 -m "chebupelkajev v0.1.1: module separation and versioned learning"
git push origin main
git push origin v0.1.1
git status --short --branch
git show --no-patch v0.1.1
git ls-remote origin refs/heads/main refs/tags/v0.1.1 'refs/tags/v0.1.1^{}'
```

Перед коммитом нужные файлы должны быть добавлены через `git add`. `git push origin main` не отправляет тег автоматически. У аннотированного тега есть отдельный объект; строка с `^{}` в удалённой проверке показывает коммит, на который он указывает.

Тег опубликованной версии не передвигаем и не заменяем. Для исправления создаём новую версию. GitHub Release является отдельным объектом и не создаётся автоматически командой `git tag`.

## Паспорта учебных версий

Каждый пакет уроков содержит `version.md`: тег, способ получения полного SHA, пути файлов внутри снимка, требования к окружению, настройки API, команды и фактически проверенные сценарии. Паспорт старого выпуска может содержать уже известный SHA. Для нового выпуска используем тег и `git rev-parse 'v0.1.1^{}'`, поскольку собственный окончательный SHA нельзя записать внутри того же коммита.

## Создать отдельный снимок

Из корня, если соседняя папка ещё не существует:

```bash
git worktree add --detach ../chebupelkajev-v0.1.0 v0.1.0
cd ../chebupelkajev-v0.1.0
uv sync --locked
```

В нашей сессии эта папка уже создана; повторный `worktree add` не нужен. Если требуется самостоятельная папка для v0.1.1, после публикации тега:

```bash
git worktree add --detach ../chebupelkajev-v0.1.1 v0.1.1
cd ../chebupelkajev-v0.1.1/agent
uv sync --locked
uv run python -m unittest discover -s tests -v
```

`--detach` открывает конкретный коммит без изменения основной ветки. Для сохранения экспериментов внутри старого worktree можно создать ветку `git switch -c lab/v0.1.0`. Все worktree разделяют историю и ссылки Git, но имеют отдельные рабочие файлы и окружения. Команды восстановления не запускают модель.

Для проверки зарегистрированных папок выполни из любого worktree:

```bash
git worktree list
git rev-parse HEAD
git status --short
```

Не редактируй `uv.lock` при восстановлении снимка: `uv sync --locked` должен использовать его согласованное состояние. При отсутствующих пакетах или Python могут понадобиться загрузки. Версия `3.14` выбирает ветку Python; проверенный патч `3.14.7` фиксируется в паспорте, а при необходимости выбирается явно через `uv sync --locked --python 3.14.7`.

## Границы воспроизводимости

Git сохраняет код и документы, lock-файл сохраняет версии пакетов, но доступность файлов пакетов и интерпретатора зависит от кеша или сети. Модель `deepseek-flash` является именем облачного сервиса; тег проекта не фиксирует её внутреннюю версию или точные ответы. Локальные tests/fixtures проверяют Python-цикл без сети, а облачный запуск отдельно проверяет текущую совместимость с DeepSeek. Секреты не входят в снимок.

## Право исполнения Markdown

По запросу владельца `VERSIONING.md` и `CHANGELOG.md` имеют файловый режим `100755`, установленный через `chmod +x`. Это обычные Markdown-документы без shebang и встроенного сценария. Право исполнения не делает их командами: не запускай `./VERSIONING.md` или `./CHANGELOG.md`. Читай документы и выполняй выбранные команды из блоков отдельно.
