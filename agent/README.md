# Запуск chebupelkajev

В `agent/` находится рабочий Python-проект версии **v0.1.1**. Агент получает задачу из терминала, обращается к DeepSeek и выполняет команды, которые модель передаёт инструменту `bash`. Исходник [chebupelkajev.py](chebupelkajev.py) побайтово совпадает с кодом выпуска v0.1.0. В v0.1.1 изменены расположение файлов и метаданные версии, добавлены локальные проверки.

## Подготовка окружения

Нужны Git и [uv](https://docs.astral.sh/uv/). Для обращения к модели также нужны ключ DeepSeek и доступный баланс API. Блок ниже сначала клонирует репозиторий, затем переходит в `agent/`. После этого команды подготовки, запуска и тестов выполняются из этой папки.

```bash
git clone https://github.com/alanbigulov/chebupelka-jev.git
cd chebupelka-jev/agent
uv sync --locked
```

Если репозиторий уже клонирован, из его корня выполни `cd agent`, затем `uv sync --locked`. `uv` создаст `agent/.venv` и при необходимости загрузит Python. [Файл .python-version](.python-version) выбирает Python 3.14, а [pyproject.toml](pyproject.toml) задаёт формальный минимум 3.10. Единственная прямая внешняя зависимость проекта, `requests`, зафиксирована вместе с транзитивными зависимостями в [uv.lock](uv.lock).

Ввод ключа без отображения символов в **zsh**:

```zsh
read -rs "DEEPSEEK_API_KEY?Вставь ключ DeepSeek и нажми Enter: "
printf '\n'
export DEEPSEEK_API_KEY
```

Ключ действует в текущей сессии терминала. Программа читает `DEEPSEEK_API_KEY` при импорте и не загружает `.env` автоматически. В новом терминале введи ключ снова.

```bash
uv run python chebupelkajev.py "Вызови инструмент bash ровно один раз с командой pwd. Затем сообщи текущую директорию и заверши работу. Файлы не изменяй."
```

Агент выполняет команды с правами пользователя, без подтверждения и изоляции. Текст задачи не ограничивает доступ к файлам и сети. Для запуска используй отдельную учебную директорию и учитывай платные запросы API.

## Что выполняется при запуске

```text
Задача CLI -> agent_loop() -> call_llm() -> DeepSeek
                  ^                           |
                  |          +----------------+--------------+
                  |          |                               |
                  |     tool_calls                     обычный ответ
                  |          |                               |
                  |     call_tool()                      завершение
                  |          |
                  +-- история <-- run_bash() <-- системная команда
```

| Настройка | Текущее значение |
|---|---|
| API URL | `https://api.deepseek.com` |
| Модель | `deepseek-flash` |
| Режим рассуждений | `thinking: {"type": "disabled"}` |
| Ключ | Переменная окружения `DEEPSEEK_API_KEY` |
| Предел цикла | `MAX_TURNS = 1000` |
| Таймаут команды | 120 секунд |

Модель выбирает действие, Python выполняет команду и возвращает результат модели. Название инструмента `bash` не выбирает Bash: `shell=True` использует системную оболочку. HTTP-таймаут не задан. История существует только в памяти текущего запуска. Обработка нескольких вызовов инструментов, ошибок HTTP и некорректных аргументов остаётся в [roadmap](../coding-agent-developement/development-roadmap.md).

## Проверки без API

Из `agent/`:

```bash
uv run python -m unittest discover -s tests -v
```

Для этих тестов реальный API-ключ не нужен. Тесты временно подставляют `synthetic-test-key` при импорте агента, затем восстанавливают окружение. До запуска `agent_loop()` они подменяют `requests.post`, поэтому запросы к DeepSeek не отправляются.

| Fixture | Проверяемое поведение |
|---|---|
| [text_response.json](tests/fixtures/text_response.json) | Обычный ответ завершает цикл без вызова инструмента |
| [pwd_tool_cycle.json](tests/fixtures/pwd_tool_cycle.json) | Один вызов `bash` с `pwd`, результат и ID вызова во втором запросе, затем финальный ответ |

Оба JSON-файла содержат **синтетические** ответы, созданные вручную для тестов. Они не являются сохранёнными ответами облачного сервиса и не содержат реальные ключи. Во втором тесте защитный перехватчик разрешает только `pwd`, исполняет его через `subprocess.run(["pwd"], timeout=5)` и считает число команд. Тест сверяет всю историю второго запроса с ожидаемой, включая вывод команды и `tool_call_id`.

Тесты используют стандартный `unittest` и текущую зависимость `requests`; дополнительных пакетов нет. Они покрывают два базовых сценария. Несколько инструментов, ошибки и лимит ходов пока не проверены, поэтому задача EDU-06 выполнена частично. Работу DeepSeek в облаке эти проверки не подтверждают.
